# M4 Static Dispatch Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a self-contained, interactive static M4 dispatch-console prototype for stakeholder communication without calling real AI, EMS, or device APIs.

**Architecture:** One standalone HTML file owns the demo markup, styles, fixtures, state transitions, validation, and SVG schedule rendering, matching the repository's existing M3 single-file dashboard pattern. A Node/Playwright end-to-end test serves the real file locally and verifies user-visible behavior, offline boundaries, responsiveness, and browser errors.

**Tech Stack:** HTML5, CSS, vanilla JavaScript, inline SVG, Node.js `assert`, Playwright Chromium.

**Spec:** `m4/M4优化调度控制台概要设计.md`

## Global Constraints

- Output file is `m4/M4优化调度控制台.html` and opens without a build step.
- The page must visibly say `静态演示模式 · 不连接真实 AI/EMS`.
- No `fetch`, XHR, WebSocket, form submission, or external static resources.
- AI only generates a strategy draft; M4 does not directly control PCS/BMS; EMS is the sole execution layer.
- Strategy horizon is 24 hours with 96 quarter-hour points for two storage systems.
- The page has three user areas: strategy workbench, strategy/execution records, and 4.1–4.5 acceptance evidence.
- Human edits require revalidation; blocked strategies cannot be sent to the EMS simulation.
- The page does not claim that demo evidence is a formal acceptance pass.
- Page-wide horizontal overflow is forbidden at 320px; timeline-local scrolling is permitted only if labels remain usable.

```javascript
assert.strictEqual(await page.locator("#demo-mode").textContent(), "静态演示模式 · 不连接真实 AI/EMS");

await page.getByRole("button", { name: "执行安全预检" }).click();
assert.strictEqual(await page.locator("#validation-state").getAttribute("data-state"), "blocked");
assert.strictEqual(await page.locator("#send-ems").isDisabled(), true);

await page.locator("#edit-power").fill("420");
await page.getByRole("button", { name: "保存调整" }).click();
await page.getByRole("button", { name: "执行安全预检" }).click();
assert.strictEqual(await page.locator("#validation-state").getAttribute("data-state"), "passed");
assert.strictEqual(await page.locator("#send-ems").isEnabled(), true);

await page.getByRole("button", { name: "发送给 EMS" }).click();
assert.match(await page.locator("#ems-result").textContent(), /EMS 已接收/);
assert.ok(await page.locator("#record-list .record-item").count() >= 4);

await page.getByRole("tab", { name: "验收看板" }).click();
assert.strictEqual(await page.locator(".acceptance-item").count(), 5);
assert.match(await page.locator('[data-acceptance="4.5"]').textContent(), /口径待确认/);
```

### Task 2: Implement the self-contained static console

- [ ] **Step 1: Add the semantic page shell and visual system**

Create a Chinese HTML5 page with these stable elements:

```html
<main id="m4-console">
  <header><!-- title, #demo-mode, status, #theme-toggle --></header>
  <nav role="tablist" aria-label="M4 功能区">
    <button role="tab" aria-controls="workbench-panel">策略工作台</button>
    <button role="tab" aria-controls="records-panel">策略与执行记录</button>
    <button role="tab" aria-controls="acceptance-panel">验收看板</button>
  </nav>
  <section id="workbench-panel" role="tabpanel">
    <div id="schedule-points" data-point-count="96"></div>
    <button type="button">编辑策略</button>
    <button type="button">执行安全预检</button>
    <button id="send-ems" type="button">发送给 EMS</button>
  </section>
  <section id="records-panel" role="tabpanel" hidden>
    <div id="record-list"></div>
  </section>
  <section id="acceptance-panel" role="tabpanel" hidden>
    <article class="acceptance-item" data-acceptance="4.1"></article>
    <article class="acceptance-item" data-acceptance="4.2"></article>
    <article class="acceptance-item" data-acceptance="4.3"></article>
    <article class="acceptance-item" data-acceptance="4.4"></article>
    <article class="acceptance-item" data-acceptance="4.5"></article>
  </section>
</main>
```

Reuse the M3 dashboard's light/dark palette and typography direction without importing or modifying the M3 file. Add responsive grids, visible focus states, non-color status labels, and `aria-live="polite"` for validation and EMS results.

- [ ] **Step 2: Add realistic demo inputs and strategy presentation**

Embed fixture data for two storage systems and six editable strategy segments representing a complete 96-point plan. Render:

- input summary cards for forecast load, SOC, PV reference, tariff version, EMS readiness, and dispatch objective;
- an inline SVG 24-hour schedule with one lane per storage, plus tariff bands and axis labels;
- AI rationale, effect estimates, and risk notices;
- a strategy segment table with edit controls;
- `#schedule-points[data-point-count="96"]` as the machine-readable horizon contract.

- [ ] **Step 3: Implement deterministic local state transitions**

Implement tab switching, theme switching, segment editing, validation, EMS simulation, record creation, and scenario switching. Validation must use literal demo safety bounds and return one of `passed`, `warning`, or `blocked`; power above `1000 kW`, invalid time order, SOC outside `10–95%`, or missing mode must block sending. Every manual change invalidates the previous validation.

The EMS button must never perform network I/O. When clicked after a passed validation, it appends an execution record using `textContent`, changes `#ems-result` to `EMS 已接收 · 等待执行回读`, and updates the acceptance evidence state without claiming formal passage.
