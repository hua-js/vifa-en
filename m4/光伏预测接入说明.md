# M4 滚动光伏预测输入

电站2滚动优化通过原有 NocoBase 只读连接读取 energy_pv_forecast_runs 和 energy_pv_forecast_points，凭据需拥有两表 list 权限。无需额外 Socket 挂载、collections 管理权限或自动任务。

最新批次按 as_of、id 倒序选取，仅允许 ES02 / operational / completed，且 as_of 和 generated_at 不晚于读取时刻。源批次必须15分钟连续96点，核验关联、时间、步数和有限非负功率。来源版本绑定批次、内容哈希、模型、天气批次、计划起点和实际读取值；没有重算训练或复验原始天气，完整发布校验仍由光伏发布服务负责。

适配器按计划起点精确匹配区间开始时间 target_time，以 M3 负荷确定的95/96点窗口参与优化。不会拼接旧批次、补零或自动退回历史参考。as_of 达到2小时即不可用（沿用光伏查询服务时效口径）；未覆盖本轮末尾也不可用。因此当前手动模式应先生成光伏预测，再及时刷新M4输入。读取结束和生成求解请求时重新校验时效与覆盖。

电站1仍为零光伏；自然日全天比较仍调用原历史参考入口，不以未来滚动预测替代已过去的自然日数据。优化核心与设备下发接口未修改。

## 部署与使用

1. 更新M4后端镜像（包含新增 m4_settings/pv_forecast_source.py 及 live_inputs.py、upstream.py），沿用现有数据源凭据。仅更新M3/PV镜像不能让M4启用此功能。
2. 同步 m4/node-red/m4_customer_template.html 到现有M4模板节点；仓库 m4_customer_flow.json 的HTML节点也已同步。页面新增光伏预测模型、更新时间与覆盖点数展示，接口地址不变。
3. 在光伏Flow手动生成一次预测并等待完成，再在M4电站2刷新真实输入；光伏来源就绪后生成候选，仅供预览。
4. 若提示缺失、过期或窗口覆盖不足，重新生成光伏预测后刷新；若提示读取失败，检查M4凭据的两表list权限。
