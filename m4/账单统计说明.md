# M4 账单统计

2026-09-09：客户运行页面新增“账单统计”页签。按全局电站选择及月份查询，默认北京时间本月；两站分别记住当前选择月份。支持月度指标、每日明细、日月差额核对和 UTF-8 CSV 导出。全场模式需先选择单站。

## 数据与口径

只读接口：`GET /m4-api/stations/{station_id}/bills?month=YYYY-MM`。仅支持现有 `station-1 / ES01`、`station-2 / ES02`，月份范围 2000-01 至 2099-12。

| 内容 | 来源 | 使用字段 |
|---|---|---|
| 日电量 | `t_es_stat:list` | `day_charge`、`day_discharge`（kWh） |
| 日收支 | 同上 | `charge_cost`、`discharge_earnings`、`day_earnings`（元） |
| 月电量 | `t_es_count_stat:list` | `month_charge`、`month_discharge`（kWh） |
| 月收益 | 同上 | `month_earnings`（元） |
| 月表其他金额 | 同上 | `month_costs`、`month_income`、`profit`，接口保留，客户页面不展示 |

两表均以 `es_sn` 精确筛选电站，以 `createdAt` 转北京时间确定日/月归属，查询范围为月初包含、下月月初不包含；`updatedAt` 仅表示记录更新时间。实际样例在北京时间零点创建新日/月记录，未发现独立账期字段。此归属方式在本说明记录；若上游补录不遵循创建日期归属，须改用经确认的业务日期字段。

月统计直接展示月表值，日合计累加已返回日记录的两位小数展示值；差额为月值减日合计。二者分别展示，不互相替换，不把累计字段 `e_charge/e_discharge/total_earnings` 当作当月数据。保留负收益与零值，缺失显示“—”；某日某字段缺失时不输出该字段日合计。

当前月为“本月累计 · 持续更新”；过去月份为“历史月统计”。两表未提供需量电费、正式结算状态、基准电费及可比条件，因此不输出正式结算、节费率或达标结论。原独立演示模式仍保留 Mock 账单，真实运行模式使用本页。

## 完整性与隔离

- 使用现有固定上游域名、GET、禁止重定向和分页完整性检查；单表最多读取 2 页，每页 100 条，超限报错而非截断后汇总。
- 返回数据再次校验电站、月份、带时区时间及有限数值。同月多条月记录、同日多条日记录使对应来源报错，不重复计算或擅自选最新。
- 一张表失败时保留另一张表，并显示失败信息；两张表失败时显示错误。缺日期按历史整月或本月至今天检查，仅代表记录覆盖，不代表每日结算完成。
- 按需查询与手动刷新，不跟随调度轮询反复请求。切站、切月取消旧请求，并以请求版本阻止旧响应覆盖。接口与页面均不写统计表、不触发求解或设备下发。
- iframe 请求复用现有 Bearer Token；Node-RED 仅转发合法月份，过滤其他浏览器查询参数。

## 收益趋势与月份对比（2026-09-09 补充）

- 收益趋势显示每日充电成本、放电收益、净收益（沿用 `day_earnings`），支持分别开关曲线、点击时点和键盘/拖动日期滑块查看精确值。缺少日期或字段时曲线断开，负收益保留在零线下方；手机可横向滚动。
- 每次查询复用既有账单 API，并行请求所选月与上月。主月先显示，上月失败仅影响对比区；切站/切月取消两次请求，并用同一请求版本防止迟到数据覆盖。没有新接口、网关变更或后台轮询。
- 查询月份等于北京时间当前月时，两期均取1日至今天；上月天数不足时，两期都截取到上月最后一天。例如3月31日与2月比较，平年双方只取1–28日、闰年取1–29日。今天还未结束，上月对应日已是全天，页面明确提示这不是同一时刻对比。
- 历史月份与紧邻上月按各自整月比较，保留月份实际天数差异，并显示完整日期范围及记录覆盖。未来月份不比较；2000-01没有支持范围内的上月，不发出1999-12请求。
- 对比的电量、充电成本、放电收益和净收益统一使用日表汇总，不混用月表值。某期缺日或每日来源失败时，该期全部合计缺省；单项字段缺失仅影响该项。任一期某项合计缺省时，不计算该项变化。
- 变化量=本期−上期；仅在上期值为正数时计算变化率。零或负基期保留金额变化并隐藏比例，避免造成误导。比较只描述统计变化，不认定为调度节费。
