# M4 求解器决策

更新：2026-09-08。M4 主链已改为 Pyomo 6.10.1 + HiGHS 1.15.1：调度建模和最终候选选择均由数学求解完成。AI 退出决策。

## 本地使用

项目目录 `vifa/` 下同步依赖：

```sh
uv sync --locked
```

沿用本地服务启动方法（见[调度参数配置说明](调度参数配置说明.md)），打开 `/m4`，在“调度运行”页面点击“生成调度计划”（已有结果时为“重新生成计划”）。读取或刷新页面不会自动触发计算。CLI 使用相同本地 API：

```sh
.venv/bin/python -m m4_selection.decision_chain --station station-1
.venv/bin/python -m m4_selection.decision_chain --station station-2
```

`--api-base` 默认 `http://127.0.0.1:8844`，`--output` 可指定新的独立运行目录。默认记录位于 `m4/run/solver-decisions/<station_id>/<run_id>/`，可用 `M4_DECISION_RESULTS_DIR` 指定根目录。退出码0为完成、1为业务阻断、2为启动或参数错误。缺参数、缺偏好或输入未就绪时不会伪造计划。

## 日常界面

主页优先展示最近生成的计划、24 小时充放电曲线、预计净电费和最大购电功率；曲线默认展开，96 点明细、其他方案和技术记录按需展开。费用均为计划预测值，历史记录不代表当前可执行计划。

右侧“运行准备”集中显示参数、运营偏好和数据校验状态，提供对应配置入口；“数据与设备状态”保留来源与柜级排除原因。分步候选计算、单独选择、候选预览和诊断记录收在“高级分析”。主页不显示模拟月度节费。

“执行状态”如实显示 EMS 下发、执行回读尚未接入，自动滚动调度未启用。此界面调整不增加真实设备操作。

## API

各路径位于 `/m4-api/stations/{station_id}/`：

| 路径 | 用途 |
|---|---|
| `POST decision-runs` | body为 `{"request_id":"UUID-v4"}`，启动一次后台预览；同一ID幂等 |
| `GET decision-runs` | 当前/最近后台运行，包含阶段、开始/结束时间与中断状态 |
| `GET decision-result` | 最近结束的历史记录，包含最终方案、理由、比较、96点计划及求解信息 |
| `POST selection` | 对当前候选快照执行数学选择和实时复核；使用原候选轮次与偏好revision |

2026-09-08 按用户要求删除模型适配器、配置、旧 CLI、AI 接口、专属测试、评测及原始记录。旧 `ai-runs` / `ai-selection` 路径不再注册（404），不再提供历史模型记录读取。

## 结果与约束

三候选仍分别计算，保留既有跨方案需量比较。最终单选模型将精确指标顺序编码为小整数目标，原始十进制容差决定每层保留集合，避免数值尺度影响经营偏好。最终输出由独立确定性程序复核，不允许超时/可行但未证实最优的选择结果通过。

电站1已保存的 `profile_priority` 和 balanced/cost/pv 顺序保持原值；电站2偏好不自动补齐。SOC、功率、设备状态、期末SOC、PV规则、目标顺序及谷段重排规则均保持原口径。新建模框架可能得到同目标值的另一套合法计划；逐点变化不能单独视为经营规则变化。

`solver_name=pyomo-highs`，版本同时报告实际 HiGHS 与 Pyomo，模型标识追加 `/pyomo-v1`，最终决策版本为 `pyomo-highs-selection-v2`。编排仅接受 `m4-orchestration-v2 / pending_selection`。离线示例使用当前求解器重新生成，旧编排 v1 文件须重新求解后导入。优化器自身的历史数学计划复验仍保留。

新记录保存配置、偏好、输入、候选、选择和报告，并绑定文件摘要。读取记录时核对站点、轮次、版本、计划、比较和有效期；读取失败不回退显示更早记录。历史卡片始终是历史预览，不保证此刻现场仍有效。

所有结果均为计划预览，EMS未下发。本次迁移未连接生产或模型服务，未修改客户配置。验证结果以本轮交接记录为准。
