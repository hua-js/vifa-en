# M3 人工部署手册

现行生产架构固定为：AMD64 Docker 双容器、三域 HTTPS、Node-RED 固定访问 Unix Socket、
NocoBase 普通 iframe URL、OPDash 看板公开只读。

完整操作见：[AMD64三域Docker部署手册.md](./AMD64三域Docker部署手册.md)。

## 临时安全例外与待办（2026-08-28）

当前生产更新暂时跳过专用 Worker 最小权限角色配置，允许将绑定 `root` 角色的 API Key 作为
`M3_NOCOBASE_API_KEY` 使用。该决定仅是临时生产例外，不改变本手册后续章节和机器合同规定的
最终最小权限目标；文档不得记录 Key 明文。

已知风险：Worker 在例外期间拥有超出 M3 所需范围的全局查看、新增、更新、删除、导入和导出
权限。应限制密钥接触范围，禁止将其写入日志、命令参数、工单或截图；发现疑似泄露时立即轮换。

高优先级待办：

1. 创建专用 `m3_worker` 角色，关闭全局默认权限；
2. 按 `m3/contracts/nocobase_collections.json` 配置八个 M3 集合的最小动作和字段权限，其中新增三表分别只允许：
   `manual_runs` 的 `list/update/firstOrCreate`、`manual_points` 的 `list/create`、
   `manual_evaluations` 的 `list/updateOrCreate`；
3. 生成绑定 `m3_worker` 角色的新 API Key，并替换生产 `/etc/vifa-m3/m3.env` 中的
   `M3_NOCOBASE_API_KEY`；
4. 使用新 Key 重新执行任务、完整批次、`writing` 批次和评估四个只读探针；
5. 四个探针全部返回 HTTP 200 后，从 Worker 配置中移除 root Key，并撤销不再使用的临时 Key。

关闭条件：生产 Worker 使用专用最小权限 Key，四个只读探针通过，root Key 不再出现在 Worker
运行配置中。完成前不得将此待办标记为关闭。

本手册现在用于生产重部署、检查和回退，不再作为首次上线状态说明。

## 唯一生产交付入口

```text
compose.yaml
m3/node_red/m3_production_gateway_flow.json
m3/nocobase/m3_nocobase_iframe_manifest.json
m3/nocobase/M3普通iframe配置说明.md
m3/AMD64三域Docker部署手册.md
```

不要导入 `energy_forecast_flow.json`、`m3_dashboard_page_flow.json` 或旧 JS Block。

## 固定边界

- Docker 平台为 `linux/amd64`；
- 同一镜像运行 Worker 和 Dashboard 两个容器；
- Docker 不开放 TCP 端口；
- Node-RED 与 M3 Docker 同机，通过固定 Unix Socket 通信；
- NocoBase 使用普通 iframe URL，不使用 Header、JavaScript Block或 postMessage；
- `/ett` 与 `/energy-forecast-api` 对任何能访问 OPDash 的用户公开；
- 不修改反向代理、M1/M2 或四个既有 M3 结果/明细集合；
- 不重启 Node-RED；
- 新镜像部署前后均以 `M3_ACCEPTANCE_ENABLED=false` 为安全默认值；按以下流程才可改为 `true`。

## 连续七日验收生产启用

四个既有结果/明细集合保持不变：`energy_forecast_latest`、`energy_forecast_batches`、`energy_forecast_points`、`energy_forecast_evaluations`。详细证据仍写入 batches、points、evaluations；新增的第五个集合 `energy_forecast_acceptance_runs` 仅是控制/汇总表，不重复存储指标。

操作员在 NocoBase 创建并拥有任务身份、窗口和控制字段；Worker 列出任务行，且只能更新 `completed_days`、`result_state` 和 `calculated_at` 三个汇总字段。Worker 只配置一个专用 `M3_NOCOBASE_API_KEY`；同一个角色合并既有明细写权限、新增批次/评估限定读取和任务汇总更新权限，不另配验收任务 Key。以下是示例，不是生产 ID：

```text
station_id:          ES01-FULL-ID-EXAMPLE
acceptance_run_id:   acceptance-20260829-station1
window_start:        2026-08-29T01:00:00+08:00
window_end:          2026-09-05T01:00:00+08:00
control_state:       active
completed_days:      0
result_state:        pending
calculated_at:       留空
```

日期仅为示例。每个真实任务都从上海时间 01:00 开始，恰好七天后结束，并必须在首日 01:02 调度槽之前创建。

以下探针用同一个 Worker Key 覆盖任务、完整批次、`writing` 恢复批次和评估的固定读取合同。Authorization 头从 stdin 传给 curl，不出现在 curl argv。不得用生产记录测试写入；在 NocoBase 角色 UI 中核验同一 Key 只有：latest `list/updateOrCreate`、batches `list/update/firstOrCreate`、points `list/update/firstOrCreate`、evaluations `list/updateOrCreate`、acceptance runs `list/update`，并逐项核对机器合同中的字段/过滤/排序/写入/记录键。

```bash
read -rsp 'Worker NocoBase token: ' M3_PROBE_TOKEN
echo
read -rp 'Full station ID: ' M3_STATION_ID
read -rp 'Acceptance run ID: ' M3_ACCEPTANCE_RUN_ID
printf 'Authorization: Bearer %s\n' "${M3_PROBE_TOKEN}" | curl --fail --silent --show-error \
  --header @- \
  --get 'https://vifa.hlszh.com/api/energy_forecast_acceptance_runs:list' \
  --data-urlencode "filter={\"station_id\":\"${M3_STATION_ID}\",\"control_state\":\"active\"}" \
  --data-urlencode 'fields=id,station_id,acceptance_run_id,window_start,window_end,control_state,completed_days,result_state,calculated_at' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=1000'
printf 'Authorization: Bearer %s\n' "${M3_PROBE_TOKEN}" | curl --fail --silent --show-error \
  --header @- \
  --get 'https://vifa.hlszh.com/api/energy_forecast_batches:list' \
  --data-urlencode "filter={\"station_id\":\"${M3_STATION_ID}\",\"acceptance_run_id\":\"${M3_ACCEPTANCE_RUN_ID}\",\"write_state\":\"complete\"}" \
  --data-urlencode 'fields=station_id,acceptance_run_id,issued_at,forecast_start_time,forecast_end_time,write_state' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=1000'
printf 'Authorization: Bearer %s\n' "${M3_PROBE_TOKEN}" | curl --fail --silent --show-error \
  --header @- \
  --get 'https://vifa.hlszh.com/api/energy_forecast_batches:list' \
  --data-urlencode "filter={\"station_id\":\"${M3_STATION_ID}\",\"write_state\":\"writing\"}" \
  --data-urlencode 'fields=id,station_id,acceptance_run_id,issued_at,forecast_start_time,forecast_end_time,status,write_state,model_manifest,content_hash,point_templates' \
  --data-urlencode 'sort=issued_at' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=1000'
printf 'Authorization: Bearer %s\n' "${M3_PROBE_TOKEN}" | curl --fail --silent --show-error \
  --header @- \
  --get 'https://vifa.hlszh.com/api/energy_forecast_evaluations:list' \
  --data-urlencode "filter={\"station_id\":\"${M3_STATION_ID}\",\"acceptance_run_id\":\"${M3_ACCEPTANCE_RUN_ID}\"}" \
  --data-urlencode 'fields=station_id,acceptance_run_id,evaluation_key,window_start,window_end,outcome,calculated_at' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=1000'
unset M3_PROBE_TOKEN M3_STATION_ID M3_ACCEPTANCE_RUN_ID
```

严格按以下顺序操作：

1. 核验表约束和 Worker 角色权限。
2. 在 `M3_ACCEPTANCE_ENABLED=false` 下部署新镜像。
3. 为每个需要启用的电站创建一个活动任务。
4. 核验每个活动/空电站查询。
5. 在 `/etc/vifa-m3/m3.env` 中设置 `M3_ACCEPTANCE_ENABLED=true`。
6. 在首个 01:02 槽之前只重建 `vifa-m3-worker`。
7. 在 01:02 后检查首个完整 batch 和任务汇总。
8. 在最终实绩回填和评估完成前保持 `control_state=active`。
9. 仅在 Dashboard 显示终态 7/7 结果后将任务标记为 `completed`。

启用自定义预测需要重新导入 `m3_production_gateway_flow.json` 并使用 `Deploy Modified Flows`。
`server_token` 模式继续只读；写操作必须使用 `postmessage` 当前用户认证，并在 Node-RED 服务端配置与
Worker 一致的 `M3_STATIONS_JSON` 和 `M3_WORKER_ADMIN_TOKEN`，不得把管理令牌传给浏览器。
