# M3 AMD64 三域部署说明

- 页面：`https://opdash.lvkpower.com/ett`；
- API：`https://opdash.lvkpower.com/energy-forecast-api`；
- API 已返回两座电站，每座电站的总负荷和储能 SOC 均包含 96 个实绩点与

- 当前仅确认生产预测与看板链路可用；连续七日验收以 `M3_ACCEPTANCE_ENABLED=false` 为安全默认值，只有新镜像、活动任务和任务表探针均就绪后才启用。

## 职责

| 组件 | 地址/接口 | 职责 |
| --- | --- | --- |
| VIFA NocoBase | `https://vifa.hlszh.com` | 原始数据、四个 M3 结果/明细集合与验收控制/汇总表 |
| EMS NocoBase | `https://ems.lvkpower.com` | 页面和普通 iframe 容器 |
| OPDash Node-RED | `https://opdash.lvkpower.com` | `/ett`、`/energy-forecast-api`、Socket Exec |
| M3 Worker | AMD64 Docker | StatsForecast 预测、四个结果/明细集合写入及任务汇总更新 |
| M3 Dashboard | AMD64 Docker | 四个结果/明细集合与最近实绩只读聚合 |

## 数据流

Worker 主动请求 `https://vifa.hlszh.com/api/t_es_data:list`，按两个电站独立聚合、训练和预测，
然后通过 VIFA HTTP API 写入四个结果/明细集合。第五个集合 `energy_forecast_acceptance_runs` 是控制/汇总表，不重复 metrics；详细证据仍留在 batches、points、evaluations。页面刷新只读取结果，不触发训练。

## 页面流

```text
EMS NocoBase 普通 iframe
  -> https://opdash.lvkpower.com/ett（公开）
  -> https://opdash.lvkpower.com/energy-forecast-api
  -> Node-RED Exec curl dashboard.sock
  -> M3 Dashboard JSON
```

浏览器不提供 Token，Node-RED 不调用 EMS 当前用户认证。`/ett` 与 `/energy-forecast-api` 对
任何能访问 OPDash 域名的人公开。Dashboard 四个结果/明细集合的只读 Key 只存在于容器环境中，不进入 URL、
Node-RED Flow、页面源码或日志。

## Socket

```text
宿主机：/userdata/holo/pyfiles/vifa-m3/run/worker.sock
宿主机：/userdata/holo/pyfiles/vifa-m3/run/dashboard.sock
容器内：/run/vifa-m3/worker.sock
容器内：/run/vifa-m3/dashboard.sock
```

Node-RED 与 M3 Docker 必须同机，或 Node-RED 容器已经映射相同宿主机目录。Node-RED 不调用
宿主机 Python或 Docker CLI。

## 连续七日验收生产启用

操作员负责在 `energy_forecast_acceptance_runs` 创建任务身份、窗口和控制字段；Worker 只更新汇总字段。示例而非生产 ID：

```text
station_id:          ES01-FULL-ID-EXAMPLE
acceptance_run_id:   acceptance-20260829-station1
window_start:        2026-08-29T01:00:00+08:00
window_end:          2026-09-05T01:00:00+08:00
control_state:       active
completed_days:      0
result_state:        pending
calculated_at:       留空
```

日期仅为示例：真实任务均从上海时间 01:00 开始，恰好七天后结束，并在首日 01:02 调度槽前创建。

使用下列最小权限探针读取指定站的 active 任务；更新权限通过 NocoBase 角色 UI 核验，部署期间不得以改写生产任务验证。

```bash
read -rsp 'Worker NocoBase token: ' M3_PROBE_TOKEN
echo
read -rp 'Full station ID: ' M3_STATION_ID
curl --fail --silent --show-error \
  -H "Authorization: Bearer ${M3_PROBE_TOKEN}" \
  --get 'https://vifa.hlszh.com/api/energy_forecast_acceptance_runs:list' \
  --data-urlencode "filter={\"station_id\":\"${M3_STATION_ID}\",\"control_state\":\"active\"}" \
  --data-urlencode 'fields=id,station_id,acceptance_run_id,window_start,window_end,control_state,completed_days,result_state,calculated_at' \
  --data-urlencode 'page=1' \
  --data-urlencode 'pageSize=1000'
unset M3_PROBE_TOKEN M3_STATION_ID
```

1. 核验表约束和 Worker 角色权限。
2. 在 `M3_ACCEPTANCE_ENABLED=false` 下部署新镜像。
3. 为每个需要启用的电站创建一个活动任务。
4. 核验每个活动/空电站查询。
5. 在 `/etc/vifa-m3/m3.env` 中设置 `M3_ACCEPTANCE_ENABLED=true`。
6. 在首个 01:02 槽之前只重建 `vifa-m3-worker`。
7. 在 01:02 后检查首个完整 batch 和任务汇总。
8. 在最终实绩回填和评估完成前保持 `control_state=active`。
9. 仅在 Dashboard 显示终态 7/7 结果后将任务标记为 `completed`。

`m3_production_gateway_flow.json` 不需要为本变更重新导入；生产 Node-RED 保持不变。
