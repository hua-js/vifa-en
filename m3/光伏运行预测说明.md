# 电站2未来24小时光伏功率预测

**当前交付：** 已补齐9月可用历史天气并刷新训练源，生产侧按用户最新确认采用手动 Flow，详见 [生产手动 Flow 与部署说明](pv/README.md)。未启用每小时定时任务。以下命令仍可独立使用。

预测模型为 **WeatherRidge 岭回归**。沿用已验证的9个天气交互特征、训练集RMS缩放、无截距、lambda=0.01；目标是十五分钟平均交流功率，单位kW。训练样本来自已保存的ES02实测快照与历史天气交集。

## 计算与追溯

- 使用实际运行的 `as_of`，从其后下一个十五分钟开始输出96点；`forecast_end` 为不含的右端。恰好22:15运行时从22:30开始。
- 新输入必须在 `as_of` 前读取完成；实际使用功率样本及天气 `fetched_at` 均不晚于 `as_of`。未知天气发布时间继续为NULL。
- 训练至少包含7个完整日，每个实测十五分钟至少12个有效分钟，四个合格点才纳入小时。训练数据不包含标签结束晚于 `as_of` 的行。
- 训练和预测共享天气对齐函数：辐照取小时结束标签，温湿度/云量/风速插值到区间中点，降水均分四份。整批天气需要50个连续小时标签，并完整覆盖新确定的目标窗口；不混批次、不用零填补缺失。
- `raw_forecast_kw` 保留约束前结果，`forecast_kw` 将负值截为零，`is_clipped` 记录是否发生截断。写入numeric(14,6)，四舍六入五成双至六位小数；原始模型参数和输入保留可还原的浮点字符串。
- 没有确认交流额定容量，因此不假定上限。七日参考 `baseline_kw` 和预测区间上下界保持NULL；当前没有生成七日参考或估计置信区间。
- 批次 `source_manifest` 内嵌实际使用的聚合训练样本、完整预报天气快照、输入文件SHA与来源路径、聚合规则、运行环境；`model_config` 内嵌特征、缩放和系数。无需依赖原实测表后续是否变化，即可复算该批预测。
- 第一批训练截止2026-08-31 23:00，1,276点；刷新后训练截止2026-09-09 22:00，2,136点。新生产手动版使用刷新后的固定训练源。真实天气预报条件下的精度仍需待未来实测到齐后评估。

## 运行命令

在 `vifa/` 目录执行，Python需已有NumPy/Pandas。每次使用新的快照和输出目录；已存在目录拒绝覆盖。

```bash
python3 m3/deploy/fetch-open-meteo-weather.py --fetch-dir /absolute/path/weather-snapshot

PV_NOCOBASE_IMPORT_API_KEY_FILE=/absolute/path/private-key-file \
  python3 m3/deploy/fetch-open-meteo-weather.py \
  --snapshot /absolute/path/weather-snapshot --execute

python3 m3/deploy/generate-pv-forecast.py \
  --weather-snapshot /absolute/path/weather-snapshot \
  --output /absolute/path/pv-forecast-bundle

PV_NOCOBASE_IMPORT_API_KEY_FILE=/absolute/path/private-key-file \
  python3 m3/deploy/publish-pv-forecast.py \
  --bundle /absolute/path/pv-forecast-bundle --execute
```

凭据文件遵循运行服务的只读权限要求；只向固定NocoBase域名发送认证。所需权限：天气表list/create、预测批次表list/create/update、预测结果表list/create。工具没有数据库直连、设备控制、调度或定时运行入口。

`generate-pv-forecast.py` 默认使用第一轮回测已验证的永久输入快照，可通过 `--backtest-dir` 指定同格式工件；使用刷新训练源时指定 `--training-source /absolute/path/pv-training`。生产手动服务已显式指定包内刷新源。生成器不访问网络；导入器默认仅本地核验，只有 `--execute` 才写入，`--verify-only` 只读。

入库先预检三表和引用天气批次，再创建 `running` 批次，补写缺失结果。逐字段回读96点、确认时间/关联/值一致后，才更新 `completed`，随后再次回读。`content_hash` 覆盖模型、来源、运行时间与96点内容；运行状态和哈希字段自身不参与哈希。

相同工件重放会按 `run_id` 查已有数据，一致则跳过，冲突拒绝覆盖。POST不自动重试；异常时先回读实际状态，未完成的批次保留 `running`，不会被正常查询选中。首次发布或恢复尚未完成批次时，目标窗口若已经开始，拒绝继续，需生成新的未来批次。已完成批次允许事后只读核验。NocoBase多次请求不是数据库事务；这些完成门槛由本写入服务保证，不约束绕过该服务的其他写入方。

为保留首次执行证据，重放时另存报告：

```bash
PV_NOCOBASE_IMPORT_API_KEY_FILE=/absolute/path/private-key-file \
  python3 m3/deploy/publish-pv-forecast.py \
  --bundle /absolute/path/pv-forecast-bundle --execute \
  --report /absolute/path/pv-forecast-bundle/idempotence_verification.json
```

## 通过NocoBase查询

先查询 `GET /api/energy_pv_forecast_runs:list`：

```json
{
  "filter": {
    "es_sn": {"$eq": "ES02"},
    "run_kind": {"$eq": "operational"},
    "status": {"$eq": "completed"}
  },
  "sort": "-as_of",
  "pageSize": 1,
  "fields": "id,run_id,es_sn,as_of,forecast_start,forecast_end,interval_minutes,expected_points,status,model_name,model_version,training_end,weather_batch_id,generated_at"
}
```

上述为查询参数表示，`filter` 在URL中需JSON序列化并编码。取返回的 `id` 作为 `run_pk`，查询 `GET /api/energy_pv_forecast_points:list`，`filter={"run_pk":{"$eq":实际id}}`、`sort=target_time`、`pageSize=100`。界面展示查询限定字段即可，复核模型时再读取较大的 `source_manifest/model_config`。

## 本地产物

`run.json`、`points.json` 是可复算的待发布工件；其中run的completed为最终目标状态，是否实际入库必须看 `publication_verification.json`，不能从本地run状态推断数据库状态。`summary.json` 描述生成时状态；实际入库报告另存，保留生成证据不回写。

另有 `forecast_points.csv`、`training.csv`、`forecast_weather.csv`、输入副本、源码与SHA清单。`plot-pv-forecast.py` 读取成功核验记录后导出静态功率/辐照曲线，需要Matplotlib和中文字体；当前使用临时绘图依赖，未增加生产依赖。

运行时通过业务表 list 检查字段可读性，不调用 collections:get；空表允许首次写入，完整字段和值仍由入库回读校验。字段类型、索引和约束由独立建表工具检查。
