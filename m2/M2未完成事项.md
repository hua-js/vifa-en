## 2. P0：先完成真实实时页面

以下事项直接阻塞真实数据渲染，应优先完成。

### 2.1 补齐 `t_emu` 实时字段

最近一次真实接口检查返回 ES01、ES02 共 8 条设备记录，设备集合正确，但关键字段尚未完整写入。

| 字段 | 使用范围 | 当前情况 | 要求 |
|---|---|---|---|
| `latest_power` | 每个储能柜 | 已有数值 | 保持 kW；充电为负、放电为正。 |
| `latest_grid_power` | 场站主 EMU | 已有数值 | 保持 W；适配层统一除以 1000 转为 kW；正数购电、负数上网。 |
| `pcs1_power` | 每个储能柜 | 8 个柜均为 `null` | 写入有限数值；充电为负、放电为正。 |
| `pcs2_power` | 每个储能柜 | 8 个柜均为 `null` | 写入有限数值；充电为负、放电为正。 |
| `battery_power` | 每个储能柜 | 仅 emu11 有值，其余为 `null` | 每个柜均写入有限数值；方向与 PCS 一致。 |
| `load_power` | 场站主 EMU | emu11 为 0，emu26 为 `null` | 确认 ES01 的 0 是否真实；为 emu26 写入场站负载 kW。 |
| `input_ac_solar_power` | ES02 主 EMU emu26 | `null` | 写入光伏总输入功率 kW。 |
| `latest_solar_power` | ES02 主 EMU emu26 | 有字段，检查时为 0 | 保持光伏 AC 输出功率 kW；白天验证非零值。 |
| `acpv_rated_power` | 低负载判断候选输入 | 当前为 `null` | 不阻塞三条链路实时计算；若用于光伏逆变器低负载判断，需要补齐并确认单位。 |

验收标准：

- ES01 的 emu11、emu12 和 ES02 的 emu21—emu26 都能返回计算所需的有限数值；
- `build_station_source_record()` 对 ES01、ES02 均能成功返回标准记录；
- 不将 `null`、空字符串或缺失字段自动转换成 0；
- 白天和充放电两个方向各留一组真实样本完成核对。

### 2.2 确定服务端鉴权方式

当前适配器可以使用外部传入的 Bearer token 请求接口，但尚未实现登录和 token 生命周期管理。

待完成：

2. token 或登录凭据只从服务端环境变量/密钥配置读取，不写入 Python、HTML、Git 或日志；
3. 对 401/403、超时和非法 JSON 返回稳定错误；
4. 如果使用动态登录，实现 token 缓存、失效后重新登录，避免每分钟重复登录；
5. 更换已经在调试对话或命令中暴露过的 token/密码。

验收标准：服务重启后可以自行获得有效鉴权，日志和错误响应中不出现 token、密码或完整 `Authorization` 请求头。

### 2.3 实现 HTML 同源接口 `/energy-efficiency-api`

HTML 当前固定请求：

```text
GET /energy-efficiency-api
```

尚缺少实际 HTTP 服务。接口至少需要完成：

```text
校验页面用户和 station_id
    → 获取有效服务端 token
    → 请求一次 t_emu:list
    → 构造场站标准输入
    → 调用三条链路计算函数
    → 读取当日分钟点和瓶颈事件（未建表前可返回空数组）
    → 返回 HTML 已约定的 JSON
```

接口要求：

- 服务端固定数据源地址，不能让 iframe 查询参数覆盖 API 域名；
- 页面用户只能查询其有权限的场站；
- 实时计算错误需要返回可展示的错误码和简短信息；
- 暂无历史数据时允许返回实时结果、空 `trend` 和空 `events`，页面不得使用模拟数据；
- 一次页面刷新只发起一次 `t_emu:list` 请求；
- 正式环境不把数据源服务 token 下发给 iframe。

验收标准：浏览器打开 HTML 后，状态从“正在加载后端数据”变为“后端实时数据”，三条链路使用真实 API 数值渲染；接口失败时页面显示错误态且控制台无未处理异常。

## 3. P1：保存并展示当日分钟曲线

纯 Python 的分钟数据结构和当日曲线组装已经完成，缺少真实持久化和调度。

### 3.1 在 NocoBase 创建三张集合

1. `station_efficiency_points`：每场站每分钟一条效率和链路输入/输出；
2. `efficiency_bottleneck_rules`：每场站一份可配置规则；
3. `efficiency_bottleneck_events`：保存持续中和已恢复事件。

需要同时建立设计文档规定的字段、非空约束、唯一键、时间索引和访问权限。重点约束：

- `station_efficiency_points` 唯一键：`(station_id, data_time)`；
- `efficiency_bottleneck_rules.station_id` 唯一；
- 事件幂等键：`(station_id, event_type, device_id, start_time)`；
- 同一场站、事件类型和设备最多一个 `active` 事件。

### 3.2 实现每分钟计算任务

待完成流程：

1. 每分钟读取 ES01、ES02 的当前原始数据；
2. 转换并计算三条链路；
3. 使用场站本地时区归入分钟桶；
4. Upsert `station_efficiency_points`；
5. 读取瓶颈规则和所需回看窗口；
6. 打开、更新或恢复瓶颈事件；
7. 记录任务成功、跳过或失败原因。

验收标准：同一分钟重复执行不产生重复行；漏跑时保留曲线缺口，不补零、不以前值填充；页面刷新不触发写入。

### 3.3 实现当日查询

`/energy-efficiency-api` 需要按场站时区查询当日 `[00:00, 次日00:00)`：

- 返回已有分钟点，最新分钟之后留空；
- 三条链路各自保留 `null`，不因为一条无效而清空其他链路；
- 当日累计效率按有效分钟输入、输出累计计算，不平均分钟百分比；
- 查询与当日重叠的活动或已恢复事件；
- 活动事件显示到 `latest_time`，跨午夜事件在 00:00 处裁剪显示。

验收标准：一天最多返回 1440 个分钟点；刷新页面后曲线与数据库分钟记录一致。
