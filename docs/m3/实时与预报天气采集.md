# 实时与未来天气：统一 Forecast API

电站2使用 `https://api.open-meteo.com/v1/forecast`，一次请求同时获取 `current` 与 `hourly`。坐标23/113，Asia/Shanghai；保存完整原始响应、获取时间和不可变批次。

## 请求与保存

固定请求参数：

```json
{
  "latitude": 23,
  "longitude": 113,
  "timezone": "Asia/Shanghai",
  "current": "temperature_2m,relative_humidity_2m,cloud_cover,cloud_cover_low,cloud_cover_mid,cloud_cover_high,shortwave_radiation,direct_radiation,diffuse_radiation,precipitation,wind_speed_10m,is_day,weather_code",
  "hourly": "temperature_2m,relative_humidity_2m,cloud_cover,cloud_cover_low,cloud_cover_mid,cloud_cover_high,shortwave_radiation,direct_radiation,diffuse_radiation,precipitation,wind_speed_10m",
  "past_hours": 1,
  "forecast_hours": 49,
  "temperature_unit": "celsius",
  "wind_speed_unit": "kmh",
  "precipitation_unit": "mm",
  "timeformat": "iso8601"
}
```

`past_hours=1` 保留插值所需近时锚点；共50个连续小时标签，未来24小时区间还要检查结束整点天气是否齐全。每小时辐照沿用前一小时均值，降水为前一小时累计；其他天气变量按原整点瞬时值保存。

`current` 为气象模型当前值。时间保留为 `valid_at`，响应提供的统计间隔保留为 `interval_seconds`；本次为900秒。当前辐照/降水分别对应这段时间的均值/累计，不套用小时统计口径。此定义来自[Open-Meteo接口文档](https://open-meteo.com/en/docs)。

数据库复用 `energy_weather_points`，未修改表结构：

- `hourly` 每小时一行，`source_kind=forecast`、`interval_minutes=60`。
- `current` 放在该批次每一行相同的 `source_metadata.current_conditions` 中，不新增不符合原表小时粒度的物理行。字段包括时间、实际统计间隔、模型来源标识、数值及单位。
- `current_conditions.values` 里的天气数值为规范化十进制字符串，便于跨JSON/NocoBase回读保持哈希一致；使用方按单位转数值。`is_day/weather_code` 为整数。
- `fetched_at` 为完整响应接收后的时间，向上取毫秒以兼容NocoBase日期精度；微秒原接收时间保留在快照及元数据中。未知 `issued_at` 保存NULL，不以响应计算耗时或获取时间冒充发布时间。
- 批次ID含站点、请求、原始响应SHA、真实获取时间与映射版本；同一快照重试保持同一批次，重新获取形成新批次。原始API没有报告最终模型，`resolved_model` 保持NULL，另存返回网格坐标与海拔。
- 单位、时区、50个连续小时、数值范围/精度、当前值时间与来源均通过校验后才允许入库；天气空值保留NULL并标记incomplete。24小时缺必要天气时，`next_24h_weather_complete=false`，不能声称该批已经满足预测输入。

## 运行

在 `vifa/` 目录执行。先采集和离线整理，不需要NocoBase凭据：

```bash
python3 m3/scripts/fetch-open-meteo-weather.py \
  --fetch-dir /absolute/path/new-weather-snapshot
```

目录必须不存在；请求失败不会自动重试。完整响应保存为 `response.json`，请求/获取时间与SHA保存在 `envelope.json`，校验后的行与摘要保存在 `weather_rows.json`、`summary.json`。

将已校验快照入库，通过0600私有文件提供已授权凭据：

```bash
PV_NOCOBASE_IMPORT_API_KEY_FILE=/absolute/path/weather-import.token \
  python3 m3/scripts/fetch-open-meteo-weather.py \
  --snapshot /absolute/path/new-weather-snapshot --execute
```

所需权限为 `collections:get` 和 `energy_weather_points:list/create`。先读取表结构及同批次已有行，逐字段一致才跳过，仅新增缺失行；完成后整批回读并重算哈希。异常不自动重试POST；再次执行 `--snapshot` 会先查已有状态，不重新获取天气。完成后删除临时凭据文件。

只回读校验使用 `--verify-only`；可用 `--report /absolute/path/verification.json` 单独保存报告，保留首次导入记录。默认不读取或修改已有快照摘要，原始响应和时间不会因重试改写。`--fetch-dir ... --execute` 可以一次完成采集和入库，但发生入库不确定错误后应改用原目录的 `--snapshot` 恢复。

## 查询与下游使用

通过 `GET /api/energy_weather_points:list` 按 `es_sn=ES02`、`source_kind=forecast`、`source_batch_id` 查询。同一批次的任一行都有相同 `source_metadata.current_conditions`，包括当前天气时间与间隔。

选择天气批次时先限定 `fetched_at<=as_of`，再整批检查唯一时间、`expected_batch_rows`、首尾范围及覆盖窗口。读取当前值应展示它的 `valid_at` 和模型来源；预测计算应使用覆盖目标窗口的小时行，不能把当前值重复填满未来。不要按每个目标小时各选不同批次的最新值。

`summary.next_forecast_start/end` 只是以本次获取时间计算的输入覆盖检查窗口。较晚启动光伏任务时，必须按实际运行时间重新确定未来区间和天气覆盖，不能把旧摘要窗口当作仍在未来的预测。
