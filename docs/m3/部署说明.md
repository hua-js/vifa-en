## 数据与页面路径

Worker 通过 `https://vifa.hlszh.com/api/t_es_data:list` 读取两个电站的原始采样，
分别处理总负荷与储能 SOC，不合并电站。常规结果保存到四个结果/明细集合；
`energy_forecast_acceptance_runs` 保存正式七日验收的控制与汇总。

自定义和每日预测使用 `energy_forecast_manual_runs`、`energy_forecast_manual_points`、
`energy_forecast_manual_evaluations` 三个集合，保存任务、预测点和可比评估；
不会写入 `energy_forecast_latest` 或正式七日验收表。字段及权限以
`m3/contracts/nocobase_collections.json` 为准。

```text
VIFA 普通 iframe -> https://aivifa.hlszh.com/ett?token={{ ctx.token }}
  看板状态 -> /energy-forecast-api -> dashboard.sock -> Dashboard
  自定义/每日预测结果 -> /energy-forecast-api/custom-* -> worker.sock -> Worker
```

页面刷新只读取结果和对应实际值，不触发训练；手动提交与每日调度负责生成任务。
历史不足或质量不合格时返回真实的数据质量状态，不回退为演示结果。

### 原始采样本地滚动缓存（2026-10-10，已部署）

### 当前负载误差评分

M3评分继续作为结果/评估证据；2026-10-08本地M4实现已解除评分准入门槛，完整性与安全约束保留。下文2026-09-14的30%准入与发布步骤仅描述当时口径，不作为现行M4部署要求。

当前自定义/每日预测的负载卡片显示“负载加权 MAPE（夜间容差）”。使用实际质量为 valid、预测与实际均为有限数且实际非零的点。北京时间每天 `[00:00,07:00)` 和 `[21:00,24:00)` 为夜间：权重 0.25，绝对误差小于 10 kW 时贡献记 0，但保留该点的权重和分母；达到 10 kW 时使用完整百分比误差，不减去 10 kW。其余时段权重为 1，正常计算全部百分比误差，不使用 10 kW 容差。适用于两个电站及各输出粒度。

评分为 `sum(weight × error_percent) / sum(weight)`，其中仅夜间且绝对误差小于 10 kW 时 `error_percent = 0`，其他情况为 `abs(forecast-actual)/abs(actual) × 100`。卡片仅显示加权评分、实测回填数及完整/临时状态，不展示标准 MAPE、夜间容差置零点数和权重规则说明。没有有效非零实际点时显示 `—`。实际为零的点不进入任一 MAPE 分母，但计入实测回填数。原有标准 MAPE 验收统计保持不变；2026-09-14 用户确认 M4 求解准入改用此加权评分，门槛仍为 30%。

2026-09-14 起，评分由 M3 后端 `domain/current_prediction_score.py` 统一计算，结果接口的负载序列通过 `current_score` 返回；页面不再计算负载评分，M4 直接读取同一对象。标准 MAPE、预测值、选模、SOC 和近七日统计保持原用途。此变更需要同时发布 M3 Worker、M3 Template 和 M4 后端，不能仅替换 HTML。

以下命令含预测提交写操作，不下发设备控制；只适用于北京时间2026-09-28，过期将停止：

```bash
docker exec -i vifa-m3-vifa-m3-worker-1 python -u - <<'PY'
import os
from datetime import datetime
from zoneinfo import ZoneInfo
import httpx
from m3.worker.domain.custom_training_data import MAX_LOAD_FALLBACK_DAYS

if MAX_LOAD_FALLBACK_DAYS != 28:
    raise SystemExit("Worker版本不匹配")
if datetime.now(ZoneInfo("Asia/Shanghai")).date().isoformat() != "2026-09-28":
    raise SystemExit("本命令仅恢复9月28日预测，当前日期不同，请重新核对目标日期")

with httpx.Client(
    transport=httpx.HTTPTransport(uds="/run/vifa-m3/worker.sock"),
    base_url="http://localhost", timeout=60, trust_env=False,
    headers={"Authorization": "Bearer " + os.environ["M3_ADMIN_API_TOKEN"]},
) as client:
    ready = client.get("/ready")
    if ready.status_code != 200:
        print(ready.status_code, ready.text)
        raise SystemExit("Worker尚未就绪，不提交")
    latest = client.get("/v1/stations/ES01/custom-forecast-runs/latest",
                        params={"interval_seconds": 900, "forecast_days": 1})
    if latest.status_code == 200:
        record = latest.json()
        if record["forecast_start"] == "2026-09-28T00:00:00+08:00":
            print("已有当天成功任务：", record["run_id"], record["status"])
            raise SystemExit(0)
    elif latest.status_code != 404:
        print(latest.status_code, latest.text)
        raise SystemExit("无法确认当前任务，停止提交")
    response = client.post("/v1/stations/ES01/runs/custom-forecast", json={
        "history_start": "2026-08-18T00:00:00+08:00",
        "history_end": "2026-09-28T00:00:00+08:00",
        "forecast_days": 1,
        "interval_seconds": 900,
        "idempotency_key": "es01-20260928-load-recovery-v1",
    })
    print("HTTP", response.status_code)
    print(response.text)
PY
```

提交成功仅说明任务已受理。保存返回的 `run_id`，使用相同鉴权读取 `GET /v1/custom-forecast-runs/{run_id}`，确认 `succeeded`／`evaluated` 后，再读取 `/result` 核对负荷96点及历史证据。请求超时不换幂等键；先查询任务状态。仍为 `failed` 时继续检查失败阶段，不宣称恢复。尚未验证线上完整预测成功。
