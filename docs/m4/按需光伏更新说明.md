# M4 按需更新光伏预测

显式启动滚动候选或滚动求解器决策时，检查现有光伏预测。有效且覆盖本轮95/96点则复用；仅缺失、过期或覆盖不足允许自动更新。其他必需来源未就绪、光伏权限错误或数据损坏时不会触发更新。刷新输入GET继续只读；自然日比较继续原口径。

## 流程与失败处理

页面POST candidate-jobs创建后台候选任务，GET candidate-jobs?request_id=...轮询；请求标识幂等、站点隔离。后台先检查输入，有需要时经Unix Socket向PV服务发送一次POST /api/pv/ES02/runs，随后最多等待600秒。已有forecast任务可等待同一个job_id；正在运行其他操作、任务失败/被替换、连接结果不确定或超时均停止本轮，不自动重发POST。

预测完成后重新读取全部M4输入，必须与任务返回run_id一致且覆盖完整，再启动优化。已有PV服务仍负责天气采集、训练源检查、预测及入库回读。M4不创建天气或预测数据库表，不下发设备。

候选任务在进程内保留最近40个记录，服务重启不会自动恢复或重放；页面中断不取消后台任务，勿立即重复提交。滚动求解器决策继续使用原有持久化后台任务链。两者都复用同一个按需准备入口。
