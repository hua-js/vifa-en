# M4 需求访谈

日期：2026-09-12

目标：明确 M4 从站级功率计划走向 EMS 执行的职责、运行规则、异常处理和验收标准。

## 已确认背景

- 用户原话：“M4 输出站级功率，EMS 负责分配”。M4 不再承担柜间功率分配。
- 当前实现仍是计划预览，尚未接入实际设备下发或执行回读；这是实现现状，不代表用户最终目标。
- 线上 502 已定位为 M4 与 Node-RED 缺少共同网络；已提供恢复命令，尚未取得恢复结果。

## 摘要与关键决定

- 正式运行目标是自动执行；人工确认仅用于调试阶段，不是正式运行的固定审批流程。
- 正式运行每15分钟根据最新数据滚动重算并自动更新当天剩余计划，以最新实测SOC为起点，已执行时段不改写。
- 每次仅向EMS发送当前15分钟时段的站级功率目标，绑定计划版本、生效及失效时间；完整剩余计划保留在M4用于优化与展示，EMS负责柜间分配。
- 当前指令到期未收到新目标时，由EMS本地自动切回预先确认的有效原策略并记录、告警；原策略不可用则0kW待机，不无限延续旧功率，保留设备本地保护。这是目标规则，EMS能力尚待核实。
- 故障恢复后，正式自动模式读取最新SOC与设备状态，通过输入、约束校验并生成有效新计划后自动接管；不补发旧指令。调试模式仍需人工确认。
- 15分钟时段内，允许EMS为满足本地需量、SOC与设备保护约束，即时限充或调整站级放电功率，不等待M4下一轮；EMS回传实际功率及偏离原因，M4据实重算。这是保护性调整权限，不是任意改写优化计划。
- 执行状态区分已接收、已生效、功率跟踪正常；不能仅凭接收回执显示执行成功。EMS保护导致偏离时显示受限执行及原因，响应时间及容差尚未确定。
- 目前没有功率跟踪验收标准，允许偏差和响应时间未知；需调试取证及EMS能力核对，尚未批准默认阈值。
- 当前阶段以原有EMS充放计划为基准，沿用其计划功率；用户已确认两站目前均仅将08:00–10:00由放电改为0kW待机，其余时段沿用原EMS计划及功率。助手提出的任意优化功率执行方式未获确认。60kW仅为示例，原功率口径及站级换算需核对。此前15分钟滚动重算、EMS保护性调整仍保留，尚未被取消。
- 两站08:00–10:00待机属于当前数据下的优化结果，不是每日固定规则；用户确认继续每15分钟滚动判断，后续可随数据变化调整，充放电时沿用原EMS功率。
- 当前阶段M4仅允许保留、缩短或取消原EMS充放时段，保留时沿用原功率，取消时0kW待机；不在原待机时段新增充放电，不跨时段搬移。EMS本地保护性调整权限仍保留。
- 收益依据不足时保留原EMS计划；满足运行约束且有足够收益依据时才取消或缩短，避免预测小幅波动引起频繁切换。收益门槛和证据标准尚未确定；此原则不取消EMS本地保护权限。
- 取消08:00–10:00放电的实际作用是保留电量供19:00–21:00继续放电；用户说明原EMS计划执行到晚间已无可放电量。晚间沿用原EMS放电时段与功率，不是新增时段；“没电”不代表物理SOC为0。
- 当前聚焦求解器给出的充放电时段，具体功率沿用原EMS配置并由EMS执行，待机0kW；用户要求暂不展开收益依据，下一步讨论调度计划界面展示。
- 用户的确认属于产品运行规则，不等于授权本次访谈向设备实际下发。

## 问答记录

### Q1 — 新计划的生效权限（已确认）

- 问题：M4 算出一个更省钱的新计划时，你是否允许它不经人工确认，直接替换 EMS 正在执行的计划？
- 助手建议：第一阶段由人工确认后生效，先验证站级功率交接和执行回读，再考虑自动替换。
- 用户先答：“确认”。随后明确纠正：“目的是自动，人工确认仅用于调试阶段。”
- 最终口径：正式运行自动执行，调试阶段人工确认；替代此前“先人工确认、再考虑自动化”的开放式理解。

### Q2 — 一次确认的有效范围（用户纠正前提）

- 问题：你的一次人工确认，是批准一整版当天剩余时段的功率计划，还是每到一个15分钟时段都要重新确认？
- 助手建议：确认一整版当天剩余计划，EMS按时段执行；M4重新计算出不同的功率计划时，需要重新确认，不能沿用上一版批准。
- 用户原话：“目的是自动，人工确认仅用于调试阶段。”
- 处理：正式模式不设置逐时段或逐版本人工审批；调试确认范围尚未明确，后续再细化。

### Q3 — 自动运行的重算频率（已确认）

- 问题：正式自动运行时，你希望M4每天算一次并执行整天，还是每15分钟根据最新SOC、负荷与预测重新计算当天剩余计划？
- 助手建议：每15分钟滚动计算并自动更新剩余计划，以最新实测SOC为起点，历史已执行时段不改写。此为待确认建议，不代表已实现。
- 用户原话：“确认”。确认本题推荐方案：每15分钟滚动重算并自动更新剩余计划，以最新实测SOC为起点，已执行时段不改写。

### Q4 — M4与EMS之间交付什么（已确认）

- 问题：每次滚动计算完成后，M4给EMS发送整版剩余日程，还是只发送当前15分钟时段的站级功率目标？
- 助手建议：每次只发送当前时段的站级功率目标，并绑定计划版本与明确的生效/失效时间；完整剩余计划留在M4用于优化与展示。下一时段重新计算后发送，EMS负责柜间分配。通信中断后的动作单独确认。
- 用户原话：“确认”。确认本题推荐方案：单时段站级功率目标及版本/有效期，完整计划保留在M4。

### Q5 — 指令过期与通信中断（已确认）

- 问题：当前15分钟指令到期，但M4因断网、重算失败或数据不可用未送来新指令时，EMS应如何运行？
- 助手建议：不无限延续上一条功率；由EMS本地在到期后切回预先确认的有效原策略，并记录和告警。若原策略也不可用，则转0kW待机，仍保留设备本地保护。此为待确认的运行规则；EMS是否具备指令有效期、自动回退能力还需核对。
- 用户原话：“确认”。确认本题推荐的EMS本地到期回退、原策略不可用时待机及记录告警规则。

### Q6 — 故障恢复后的自动接管（已确认）

- 问题：EMS因指令到期已经回退原策略，M4恢复后，是自动重新接管，还是等待人工确认后再接管？
- 助手建议：正式自动模式下，M4重新读取实时SOC和设备状态，确认输入及约束校验通过并生成仍在有效期内的新计划后自动接管；旧指令不补发。调试模式继续人工确认。故障恢复不能直接重放失联前的计划。
- 用户原话：“确认”。确认本题推荐的正式模式重新计算校验后自动接管、旧指令不补发、调试模式人工确认规则。

### Q7 — 15分钟内突发负荷的责任边界（已确认）

- 问题：M4刚发出当前15分钟功率目标，两分钟后负荷突然上涨、购电功率接近需量上限，是否允许EMS不等待M4下轮计算，自行调整站级充放电总功率？
- 助手建议：允许EMS在本地需量及SOC/设备保护约束下即时限充或调整放电，M4目标服从本地保护；EMS回传实际执行功率与偏离原因，M4下轮使用最新实测状态重算。此为待确认的保护权限，不代表允许EMS任意改写优化计划；可执行能力需核实。
- 用户原话：“确认”。确认本题推荐的EMS本地保护性调整权限、实际执行功率及偏离原因回传规则。

### Q8 — 执行成功的证据（已确认）

- 问题：EMS返回“指令已接收”，但实际充放电功率没有跟上时，M4页面是否可以显示“执行成功”？
- 助手建议：不可以。区分已接收、已生效和功率跟踪正常：接收回执只证明收到；EMS回读当前生效指令版本证明采用；实测功率在约定响应时间和容差内跟随有效目标才算跟踪正常。EMS保护性限幅需另标“受限执行”及原因。具体响应时间、容差与接口能力后续核实，不自行设定。
- 用户原话：“确认”。确认本题推荐的三层执行证据和受限执行展示口径。

### Q9 — 功率跟踪异常的判定依据（暂无标准）

- 问题：功率允许偏差和生效后的响应等待时间，是否已有EMS/设备验收标准；若没有，是否先在调试阶段测定，再作为正式自动模式的准入条件？
- 助手建议：优先沿用已有验收标准；没有则根据两站实际功率回读频率、充放电响应、测量噪声与本地限幅行为分别测定，采用绝对kW与相对百分比结合的容差，并要求连续偏离才判异常。本次不先拍定具体数值；调试中应可观察偏差、记录证据，正式自动运行前确认阈值。
- 用户原话：“目前不知道，没有标准。功率偏差一般有几个方面”。
- 已知：目前没有验收标准，具体允许偏差和响应时间未知；不能记录为已批准任何默认阈值。用户追问功率偏差的来源，先解释分类，再继续提取异常处理偏好。

### Q10 — 保护性偏离与无原因偏离（用户转向当前阶段执行方式）

- 问题：EMS有明确保护原因、实际功率又符合其限幅后目标时，是否只显示受限执行；仅将无原因、超出响应等待时间后持续跟踪失败的偏差升级为执行异常？
- 助手建议：按上述方式分类，不把已解释的保护性偏离当成下发失败；仍记录M4原目标、EMS实际采用目标、实测功率和限制原因。保护告警自身是否需要处理，依其原等级执行。各类超时和容差仍待测定。
- 用户原话：“目前预测值可能不太准确，特别是光伏这一块。所以M4下发的目标功率可能不够。我的想法是M4这阶段下发充放计划中的功率。例如60kw”。
- 提取：用户担心预测尤其光伏不准，当前阶段倾向下发充放计划中的时段功率；60kW是示例，不是全站固定值、每柜功率或本次实际下发授权。
- 未确定：充放计划指M4最终采用计划还是EMS已有固定配置；是否改变15分钟滚动重算尚未明确。Q10异常分级尚未直接回答。
