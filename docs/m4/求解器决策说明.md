# M4 求解器决策

更新：2026-09-08。M4 主链已改为 Pyomo 6.10.1 + HiGHS 1.15.1：调度建模和最终候选选择均由数学求解完成。AI 退出决策。

## 本地使用

项目目录 `vifa/` 下同步依赖：

```sh
uv sync --locked
```

沿用本地服务启动方法（见[调度参数配置说明](调度参数配置说明.md)），打开 `/m4`，在“调度运行”页面点击“生成调度计划”（已有结果时为“重新生成计划”）。读取或刷新页面不会自动触发计算。CLI 使用相同本地 API：

```sh
.venv/bin/python -m m4.selection.decision_chain --station station-1
.venv/bin/python -m m4.selection.decision_chain --station station-2
```

`--api-base` 默认 `http://127.0.0.1:8844`，`--output` 可指定新的独立运行目录。默认记录位于 `outputs/m4/solver-decisions/<station_id>/<run_id>/`，可用 `M4_DECISION_RESULTS_DIR` 指定根目录。退出码0为完成、1为业务阻断、2为启动或参数错误。缺参数、缺偏好或输入未就绪时不会伪造计划。

## 日常界面

主页优先展示最近生成的计划、实际95或96点充放电曲线、预计净电费和最大购电功率；曲线默认展开，实际点数明细、其他方案和技术记录按需展开。费用均为计划预测值，历史记录不代表当前可执行计划。

右侧“运行准备”集中显示参数、运营偏好和数据校验状态，提供对应配置入口；“数据与设备状态”保留来源与柜级排除原因。分步候选计算、单独选择、候选预览和诊断记录收在“高级分析”。主页不显示模拟月度节费。

“执行状态”如实显示 EMS 下发、执行回读尚未接入，自动滚动调度未启用。此界面调整不增加真实设备操作。

## API

### M3 负荷数据源

M4 刷新输入时优先只读 `energy_forecast_latest` 的本站 `station_total_load`，按 `data_time`（区间起点）匹配最多未来24小时；该表的 `target_time` 是区间终点，不能直接作为 M4 起点。M3 界面、定时任务、预测算法不作修改。

现有滚动批次从当前15分钟时段开始、共96点。M4从下一时段开始，接受从该起点连续95或96点：滚动本身已有95点时直接使用，不为凑96点依赖手动尾点；滚动不足95点时兼容检查已有手动结果。最终仅末尾一格未覆盖时可采用95点；中间缺点、缺首点或不足95点仍阻断，不复制、不插值、不触发M3任务。手动表的 `target_time` 按原契约是区间起点，与滚动表分别适配。

`GET inputs` 的 `horizon_points`、`plan_end_at`、负荷/PV/电价序列保持一致：95点=23小时45分钟，96点=24小时。`sources.load` 返回实际点数、来源类型、滚动/手动点数、生成时间、覆盖范围及逐点来源。来源策略版本为 `rolling-min95-v2`，绑定实际值与批次；95点求解模型追加 `/horizon-95-v1`，期末SOC约束与费用均按实际窗口计算，旧96点记录继续独立复验。

页面动态展示来源分母、计划时长、末点、明细和历史截止时间，`warming_up/degraded` 进入提示。读取失败、错站、重复快照、损坏序列不静默回退。新批次发布前可能只剩94点，此时仍等待完整数据，不启用自动求解或EMS下发。凌晨谷段偏好仅在00:00起至已知谷段末端的标签连续完整时重排，窗口缺失该段必要标签时不推断。

各路径位于 `/m4-api/stations/{station_id}/`：

| 路径 | 用途 |
|---|---|
| `POST decision-runs` | body为 `{"request_id":"UUID-v4"}`，启动一次后台预览；同一ID幂等 |
| `GET decision-runs` | 当前/最近后台运行，包含阶段、开始/结束时间与中断状态 |
| `GET decision-result` | 最近结束的历史记录，包含最终方案、理由、比较、95或96点计划及求解信息 |
| `GET decision-history?limit=10&offset=0` | 按保存时间倒序分页读取本站历史摘要；limit 为 1–20，返回 next_offset |
| `GET decision-results/{run_id}` | 按 UUID-v4 读取指定轮次并独立复验；不存在返回404，证据错误返回503 |
| `POST selection` | 对当前候选快照执行数学选择和实时复核；使用原候选轮次与偏好revision |

2026-09-08 按用户要求删除模型适配器、配置、旧 CLI、AI 接口、专属测试、评测及原始记录。旧 `ai-runs` / `ai-selection` 路径不再注册（404），不再提供历史模型记录读取。

## 结果与约束

三候选仍分别计算，保留既有跨方案需量比较。最终单选模型将精确指标顺序编码为小整数目标，原始十进制容差决定每层保留集合，避免数值尺度影响经营偏好。最终输出由独立确定性程序复核，不允许超时/可行但未证实最优的选择结果通过。

电站1已保存的 `profile_priority` 和 balanced/cost/pv 顺序保持原值；电站2偏好不自动补齐。SOC、功率、设备状态、期末SOC、PV规则、目标顺序及谷段重排规则均保持原口径。新建模框架可能得到同目标值的另一套合法计划；逐点变化不能单独视为经营规则变化。

`solver_name=pyomo-highs`，版本同时报告实际 HiGHS 与 Pyomo，模型标识追加 `/pyomo-v1`，最终决策版本为 `pyomo-highs-selection-v2`。编排仅接受 `m4-orchestration-v2 / pending_selection`。离线示例使用当前求解器重新生成，旧编排 v1 文件须重新求解后导入。优化器自身的历史数学计划复验仍保留。

新记录保存配置、偏好、输入、候选、选择和报告，并绑定文件摘要。读取记录时核对站点、轮次、版本、计划、比较和有效期；读取失败不回退显示更早记录。历史卡片始终是历史预览，不保证此刻现场仍有效。

所有结果均为计划预览，EMS未下发。本次迁移未连接生产或模型服务，未修改客户配置。验证结果以本轮交接记录为准。

## 历史计划与对比

当前阶段仅做展示，不下发。页面顶部“历史计划”可按电站浏览已保存记录，查看单轮最终方案、95或96点安排和阻断原因；读取失败的条目单独标记，不能查看或对比。刷新、分页与查看均为GET，不触发新求解，不重新读取现场输入。首页最新计划的轮询不会覆盖历史视图。

两轮对比仅使用最终方案的共同时间点，以放电为正、充电为负，展示功率差绝对值均值/最大值及SOC差绝对值均值。周期不重叠时不绘制对比曲线。两轮净电费各自对应各自实际预测周期，不将差额解释为实际节费。附带已验证的输入摘要 `record.input_summary`，核对初始SOC、容量、功率、需量、来源版本和偏好版本变化；这些背景差异不能直接证明因果。

列表按记录文件保存时间排序，默认每页10条；浏览期间出现新记录可能改变分页位置，可刷新重新载入，前端对重复轮次去重。不导入独立试算目录，也不改变emu11告警准入规则。指定记录读取失败不会替换为其他轮次。

## 峰前电量准备提示

“最近生成的计划”中新增峰前准备卡片。历史记录经独立校验后，由服务根据最终候选和当轮预测计算：预计超限时段、峰段所需电量、该方案峰前可用电量、电量缺口，以及独立的放电功率缺口。其他候选曲线的预览不会改变此卡片。

以预测净负荷（负荷减光伏）连续超过需量上限的时段作为一个峰段；所需电池侧电量为超出部分的电量除以放电效率，可用电量取方案在峰段开始前高于安全SOC下限的储备。电量缺口折合充电侧电量时考虑充电效率，满功率补电时长仅作理论下限；容量不足、功率不足或无充电能力会单独提示，不能据此直接下发充电。

新增 `record.peak_preparation` 为只读派生字段（`m4-peak-preparation-v1`），只在最终方案完整复验后提供，绑定电站、计划版本、时间和输入来源。旧服务未提供字段时显示暂无估算；字段格式错误或跨计划绑定则拒绝展示该记录。阻断记录、读取失败、切站时不会沿用旧估算。此功能不增加实时取数、求解或EMS操作，不改变告警准入和用户参数。
