# M4 光伏余电规则与需量口径实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement the independently testable tasks below. Core behavior changes follow TDD.

**Goal:** 在本地数学核心验证客户逆流开关、余电入储和限发规则，并核对站1两柜需量口径。

**Architecture:** 保留站级96点输入/输出；新光伏规则通过明确的请求策略版本启用，历史请求保持可回放。约束构建和独立结果校验分别实现相同业务边界，LLM不能改变这些规则。

**Tech Stack:** Python、Pydantic、SciPy/HiGHS、unittest。

**Spec:** `outputs/m4/evaluations/2026-09-07-router-benchmark-v1/光伏配置规则草案.md`及本文件约束。

## 约束与范围

- 用户已确认允许逆流时按价格选择入储/外送，禁止逆流时余电在安全能力内入储，储能吸收不了允许限发/弃光。
- 本地核心和离线输入验收；不改变生产参数、保存的现场配置、页面或EMS，不调用小模型。
- 新请求显式指定`pv_dispatch_policy=load_first_economic`；缺省`legacy`保持旧输入回放，不自动启用到真实服务。
- 光伏先供本地负载；放电不能替代已有光伏供同一负载并制造外送/弃光。余电时不从电网充电。
- 禁逆流时每点充电为余量、充电功率上限、当前SOC安全空间折算的交流功率三者的最小值；不可为推荐SOC区间而弃掉本可吸收余量。
- 允许逆流时保留客户上限，外送不计入新模式`pv_unused`目标，该目标仅计算限发量；已有电费、外送收益、循环成本分项不改定义。三策略既有需量/SOC/经济目标顺序保留。
- SOC安全上下限、功率、设备许可、期末SOC仍有效。强制入储与期末约束冲突时如实返回不可行，不在最后一点擅自弃光/越界。
- 需量与负荷必须处于同一计量范围。当前读取的是站级负荷和站级need_kw，仅储能能力乘参与柜数/固定柜数；用户随后指定站1本轮临时阈值504kW，保持站级总负荷，不再把504减半；单柜分配只作说明，本轮不做EMS指令。
