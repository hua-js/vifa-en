# M4 异常柜隔离与剩余能力汇总

用户最新要求覆盖此前整站阻断规则：保留当前告警标志读取，异常柜不应阻断其他柜的充放电计划。仅修改本地输入和请求适配，不下发指令，不修改数学核心、M1 或账单。

1. 固定配置柜名单不变。每柜配置容量、功率上限按本站总配置等分；标明功率等分是当前人工边界折算，非设备实时能力。无逐柜额定/动态功率时不宣称实测能力。
2. 每柜独立检查告警、运行及部件状态、SOC、安全范围和时效（当前时刻及计划起点）。异常/未知/缺失/重复/过期柜剔除，其余柜继续。只有无参与柜或必需站级输入失败才阻断本站。
3. 调度初始 SOC 仅对参与柜按原配置柜容量加权；站级可用容量/最大充放电功率为配置总值乘参与柜数/配置柜数。保留原配置和每柜原容量，不能把剩余柜扩成整站能力。完整全站 SOC 若可计算，仅作对照。
4. 参与名单、排除名单、隔离政策和折算能力进入快照/来源版本与请求审计；构造请求时重验名单、能力、SOC及源时间。数学请求仍是一条站级计划，适用范围限定参与柜，后续 EMS 分配须遵守名单。
5. 页面区别全部参与、部分参与、不可用；展示被排除柜及原因、参与柜 SOC、可用容量/功率。只读查看真实站 1 应在其他输入完整时允许 emu12 参与。
6. 先复现旧行为的失败测试，再验证单柜告警、全柜异常、缺失/过期局部隔离、SOC/容量/功率缩减、版本改变和请求不能绕过折算；必要浏览器回归与实际渲染，独立审查关键规则。
