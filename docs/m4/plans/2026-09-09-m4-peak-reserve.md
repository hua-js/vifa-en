# M4 电站2峰段保电实施计划

> 执行方式：本会话按任务推进，独立文件并行实现并交叉审查；沿用用户此前“不测试、直接实现”要求，不运行测试套件、语法检查、浏览器测试或额外试算。不提交、不部署生产、不下发EMS。

**Goal:** 电站2全天计划不再在08:30和23点后的平段释放套利电量，优先准备峰段储能，预测下用不完的电量保留到日末。

**Architecture:** 在优化请求中显式保存可选峰段保电策略，保持旧请求序列化与滚动语义。Pyomo和独立验证同时约束非峰放电及日末SOC，全天目标优先减少首峰储能缺口。仅station-2全天启用，新策略独立版本；EMS基线仍按原配置模拟，候选末电量不低于基线且费用更低才推荐。

**Tech Stack:** 现有Python/Pydantic/Pyomo/HiGHS、本地FastAPI、单文件HTML。

**Spec:** 本任务2026-09-09用户确认“上午平段电量保留14–19；23:30–24:00电量也保留尖峰放电”。

## 约束与决策

- 当前真实电价仅gu/ping/feng；峰段为10–12、14–19，按来源标签识别，不硬编码小时或虚构独立尖峰价格。
- `peak_reserve_policy`为可选请求字段，旧None不序列化；含版本`peak-reserve-v1`及`terminal_soc_min_pct`。新目标名`peak_reserve_shortfall`。
- 非feng放电上限为满足需量/购电硬上限必需的净负荷缺口，仍受设备功率/SOC/禁止储能外送等现有边界限制。
- 新目标置于需量两层之后、其他目标之前：最小化首个feng起点相对推荐SOC上限的电量缺口。达到推荐上限后不继续奖励充电；不是无条件充到安全上限。
- 新策略日末SOC不低于max(原EMS末SOC,推荐下限)，不强制与EMS末SOC相等；保留电量和费用均按真实新计划重新计算，不篡改EMS基线。
- 当前峰段每点已到预测净负荷/功率上限，因此不能把全部平段电量强行加到峰段；原充电保持时日末约5.525%只是已存数据算术推算。实际新结果需由用户本地生成，不作为稳健控制或实测收益。
- 没有feng/标签缺失时阻断新策略；峰前准备层未完成不得标记保电已确认。旧日计划按新用途版本失效，内存和磁盘路径一致。
- 保留费用更低才推荐的门槛；若EMS被沿用，页面须明确没有采用保电优化计划。
