# M4 求解器决策架构

日期：2026-09-08。用户授权 M4 决策退出 AI，建模框架由实现方选择。

## 选择与边界

采用 **Pyomo 6.10.1 + HiGHS 1.15.1**。Pyomo 负责具名变量、约束、目标和最终候选选择；HiGHS 负责 MILP。替换主模型的手工稀疏矩阵及 SciPy milp 调用，保留独立物理复验。

相较继续手工矩阵，Pyomo 更便于审查和修改 SOC、功率、逆流、分层目标；相较换成 Julia/JuMP，它沿用现有 Python 服务、契约和校验器。HiGHS 已适用现有线性混合整数问题，本轮无需引入商业求解器或整数缩放框架。

资料：[Pyomo](https://pypi.org/project/pyomo/)、[APPSI/HiGHS 接口](https://pyomo.readthedocs.io/en/stable/reference/topical/appsi/appsi.html)、[HiGHS](https://highs.dev/)。

## 主流程

```mermaid

  I[输入与版本校验] -->|96点、参与柜| M[Pyomo 调度模型]
  P[已保存经营偏好] --> D[Pyomo 候选决策]
  M -->|分层 MILP| H[HiGHS 求解]
  H --> V[独立物理与指标复验]
  V -->|合法候选| D
  D -->|一套计划| G[实时状态与版本复核]
  G -->|通过| R[计划预览与审计记录]
  G -->|变化或过期| X[阻断，等待重新计算]
```

图合并了每个候选的分层求解细节；最终候选决策也使用 HiGHS。没有 AI 节点，EMS 下发不在本轮实现范围。

## 业务语义

- 保留 96×15 分钟、SOC/功率/末端 SOC、充放和进出电互斥、逐柜隔离、两种 PV 策略、谷段早充重排及所有分层锁。
- 为保持已确认的跨方案比较，仍求解 balanced/cost/pv 三候选。首屏突出一套最终计划，候选仅作对比；不将仅计算首选方案冒充与原语义等价。
- 最终决策依次处理需量峰值、累计超限、运营偏好与并列顺序。沿用精确十进制容差语义，数学选择结果必须通过独立确定性复核；仅在求解器证实选择最优时返回选择结果。
- 电站1保留已有 profile_priority 和 balanced/cost/pv 顺序；不修改 SQLite 偏好。缺配置或缺偏好阻断，不暗设电站2偏好。
- 区分可行解和已证明最优解；最终方案仅表示在本轮合法候选及显式偏好下的选择，不承诺全局经营最优。
- 新链路不读取 AI 配置、不调用模型、不受旧模型完成未知门禁影响；历史模型代码及记录按用户后续要求清除，其余已有改动保留。

## 接口、状态与审计

- 新增中性 decision-runs 运行与状态接口、decision-result 历史结果接口；新 CLI 使用同一无 AI 链路。
- AI 运行及历史结果接口全部删除，旧路径返回404；旧实验模块和配置全部删除。
- 编排新输出使用 m4-orchestration-v2 / pending_selection；旧 v1 契约不再接受。编排快照不被最终选择回写。
- 运行请求幂等、站间隔离、重复运行保护、重启中断可识别。新证据单独存放，保存配置、偏好、输入、候选、选择和报告；结果读取核对绑定及独立复验。
- 选择前后仍复核实时输入、参与柜、配置/偏好版本及原有效期；旧结果不因刷新恢复为当前计划。

## 验收

新增迁移和去 AI 行为测试先失败再实现；旧优化器90项作为迁移基线。覆盖无解、超时、有界差距、目标锁、负荷/PV、安全与业务回归、偏好等价性、无模型依赖、并发与证据篡改。界面查看实际渲染及基础交互，覆盖明暗模式、桌面/平板/手机。不连接生产、SSH、模型服务或设备。
