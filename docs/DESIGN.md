# VIFA 界面设计规范

适用于 M1–M4 的能源监控、能效分析、预测、调度控制台及静态 Mock。目标是让用户快速看清当前状态、变化原因和可执行操作。

## 1. 使用方式与优先级

- 页面设计任务先读本文，再读相关页面和业务文档。用户当前明确要求和项目 `AGENTS.md` 优先。
- 本文的背景基准取自实际源码；排版、组件尺寸等标为“默认”的规则用于新建或正在修改的组件，不代表现有页面已经全部达标，不要求顺带重做其他页面。
- `vifa-frontend-style` 技能提供通用方法；与本文冲突时使用本文，尤其不要用技能中的旧默认色值覆盖 M3 主题。
- 外部 DESIGN.md 只用于借鉴层级、间距和组件表达。引入时写明采用的部分，不覆盖 VIFA 背景和业务语义。

| 内容 | 权威来源与维护位置 |
| --- | --- |
| 明暗背景、面板、边框、阴影 | [M3 生产模板](../m3/node_red/m3_production_gateway_template.html) |
| M1/M2 主题适配 | [共用主题 CSS](../shared/styles/vifa-m3-theme.css)；同步方法见 [主题维护说明](../shared/styles/README.md) |
| 跨模块视觉与交互规则 | 本文，避免在各模块另建重复规范 |
| 时间、历史查询、指标及控制口径 | 对应模块业务文档和已实现的数据逻辑；视觉调整不得自行改变 |

M1/M2 必须使用 M3 背景基准；M4 新页面默认沿用这一视觉方向，现有 M4 页面按任务范围逐步适配，不因此改动生产逻辑。M3 页面维护仍直接修改唯一 HTML 模板，不同步 Flow JSON 或生成副本。

## 2. 视觉方向

安静、清晰、适度紧凑的工业能源界面。以中性背景承载数据，用少量强调色突出操作和异常。

- 层级顺序：页面标题与场站上下文 → 核心指标 → 趋势或能流 → 明细与证据 → 相关操作。
- 同一分区保留一个最强视觉重点；告警不依赖整块高饱和底色或持续闪烁。
- 使用克制的面板叠层和阴影，避免装饰性玻璃效果、重发光、巨大宣传标题。
- 中文业务标签，技术名称保持真实；图标使用同一风格的 SVG，默认 16–20px、1.5–2px 描边，不使用 emoji 代替界面图标。

## 3. 颜色与表面

以下为 M3 与共用主题源的基准快照。表中 token 使用 M1/M2 的 `--m3-*` 命名；M3 原变量去掉 `m3-` 前缀。维护时以实际主题源为准，不能只改本文就视为主题更新。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--m3-paper` | `#f4f7fb` | `#0b1020` | 页面底色 |
| `--m3-panel` | `#ffffff` | `#11182a` | 主面板 |
| `--m3-panel-soft` | `#f8fafc` | `#151f34` | 面板内分组、控件底色 |
| `--m3-panel-raised` | `#eef3fb` | `#18243b` | 提升层级的表面 |
| `--m3-ink` | `#172033` | `#eaf0ff` | 标题、主要数据 |
| `--m3-muted` | `#6f7d93` | `#8fa0bf` | 次要说明，使用前检查实际对比度 |
| `--m3-blue` | `#477df0` | `#74a7ff` | 信息、可选交互主色 |
| `--m3-cyan` | `#0e96b4` | `#5ee7f6` | 辅助强调、焦点候选色 |
| `--m3-green` | `#16855a` | `#69e6a6` | 在线、正常、成功 |
| `--m3-orange` | `#a36d00` | `#f7d26a` | 预警、需要关注 |
| `--m3-red` | `#cf4055` | `#ff7f91` | 告警、失败、危险操作 |
| `--m3-line` | `rgb(15 23 42 / 9%)` | `rgb(255 255 255 / 8%)` | 装饰性分隔与面板边框 |
| `--m3-line-hover` | `rgb(15 23 42 / 16%)` | `rgb(255 255 255 / 14%)` | 面板悬停边框 |
| `--m3-shadow-soft` | `0 14px 34px rgb(36 48 74 / 10%)` | `0 16px 36px rgb(0 0 0 / 25%)` | 主面板阴影 |

页面背景必须保留两层径向渐变：第一层位于 `12% 0%`，透明终点 `30%`；第二层位于 `86% 10%`，透明终点 `25%`。分别使用 `--m3-glow-blue`、`--m3-glow-green`，叠在 `--m3-paper` 上。

主面板使用 `linear-gradient(180deg, var(--m3-card-overlay), var(--m3-card-overlay-end)), var(--m3-panel)`；内层分组优先用 `--m3-panel-soft`，减少重复阴影。上述渐变透明度均直接复用主题源，不能只复制底色。

交互强调色可按页面用途选择。当前 M1 为浅色 `#5b5bd6` / 深色 `#a5b4fc`，M2 使用 M3 蓝色；这些是现状，不是全项目唯一允许的配色。

充电、放电、购电、上网、预测曲线的颜色先遵循页面既有图例，不能仅因通用技能建议就重新映射。新增映射必须有文字图例并在同页各图保持一致。收益为正、设备在线和功率为正是不同含义，不得由颜色推断业务状态。

## 4. 字体、尺寸与间距

默认字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。数字与表格启用 `font-variant-numeric: tabular-nums`，无需额外下载字体。

| 元素 | 新组件默认值 |
| --- | --- |
| 页面标题 | 桌面 28px，手机 22–24px；600–700 字重；1.2–1.3 行高 |
| 分区标题 | 16–18px；600–700 字重 |
| KPI 主值 | 28–32px；600–750 字重；单位 12–14px |
| 正文、表格、控件 | 14px，正文行高 1.5 |
| 次要说明、图表标签 | 12–13px；核心数据不缩到 12px 以下 |
| 间距阶梯 | 4、8、12、16、24、32px；允许沿用既有组件的 14/18px 节奏 |
| 页面边距 | 桌面 24–28px，平板 20px，手机 12–16px |
| 主面板圆角 | 16px；内层卡片 12px；控件 8–10px；状态胶囊可全圆角 |
| 控件高度 | 默认至少 40px，触屏操作区域优先至少 44×44px |

数值右对齐、标签左对齐；同组 KPI 对齐基线。单位始终可见，不能仅放在悬浮提示中。长设备名可截断，但应提供点击或键盘可访问的完整名称。

## 5. 布局与响应式

默认断点用于新布局；现有页面断点可保留，以内容可读和操作可达为验收依据。

| 宽度 | 布局行为 |
| --- | --- |
| ≥1200px | KPI 通常四列，主图与辅助明细可分栏 |
| 768–1199px | KPI 通常两列，工具栏换行，主图保留充分宽度 |
| <768px | 主内容单列；短 KPI 可两列，内容拥挤时改一列；操作不挤出屏幕 |

- Grid 子项使用 `min-width: 0`。页面不能依靠全局 `overflow-x: hidden` 掩盖被裁切的内容。
- 密集表格和能流图可在明确边界的容器内横向滚动；页面主体不横向滚动。手机上保留关键摘要和图例。
- 能流图缩放或重排后仍能辨认节点、方向、数值和单位，不能把整张图缩到文字不可读。
- 默认内容最大宽度参考 M3 的 1500px；需要宽表或大图时按内容调整，不强制所有模块同宽。

## 6. 组件与交互状态

| 组件 | 必备内容与行为 |
| --- | --- |
| 页头 | 页面名称、场站/设备范围、时间上下文；主题和查询操作可换行 |
| KPI 卡片 | 指标名、值、单位、统计范围；同比/环比要写明比较基准 |
| 按钮 | 清晰动词；一个操作组突出一个主要操作；请求中反馈进度并防止重复提交 |
| Tabs | 默认、悬停、选中、焦点、禁用状态；选中态同时有文字/边框/形状差异 |
| 筛选与日期 | 显式标签、当前值、范围错误提示；沿用既有立即查询或点击查询机制 |
| 表格 | 列头与单位明确；排序可辨认；空数据保留上下文；局部滚动不遮挡操作 |
| 状态标记 | 颜色配文字或图标；离线、未知、告警分别表达，未知不能显示为正常 |
| 弹窗/抽屉 | 标题、关闭入口、键盘焦点管理；关闭后焦点回到触发控件 |

交互控件必须覆盖 hover、active、disabled、`focus-visible`；非交互卡片无需伪装成按钮。图标按钮提供可访问名称。原生按钮和表单优先；自定义 Tabs 需匹配 ARIA 语义与键盘切换行为。

焦点默认采用 2px 可辨认轮廓、2px 偏移，不因移除浏览器默认 outline 而丢失焦点。禁用操作说明原因，不能只降低透明度。

## 7. 数据、图表与能源语义

- 区分 `kW` 功率与 `kWh` 电量；百分比、金额和电价注明单位。同类指标小数位一致，显示精度按业务需要确定，不修改底层计算精度。
- 显式区分实时、历史、预测、模拟、建议和已执行。模型产出或前端模拟不能显示成真实执行成功。
- 时间展示沿用模块既有时区与区间口径；相对时间须能查到绝对时间。区分采样时间、预测生成时间和预测目标区间。
- 缺失值显示 `—` 或“暂无数据”，不能变成 `0`；过期数据显示“数据延迟”及最后更新时间，延迟阈值沿用业务配置，不能在样式任务中发明阈值。
- 充放电和购售电的正负号按接口定义，配方向文本或箭头；不能凭数值正负自行反转能流。
- 实测与预测使用线型及文字区分，如实线与虚线；预测区间仅在有真实区间数据时展示，不编造置信带。
- 图表有轴单位、图例、时间范围和可读 Tooltip；不同量纲用明确标注的轴或分图。缺测处断开或标注，不悄悄补零或插值。
- 告警详情应可追溯到设备、发生时间和原因；历史记录保持原始事件时间。EMS 建议展示来源与约束，不新增真实设备下发动作。

## 8. 加载、空态、异常与可访问性

| 状态 | 展示要求 |
| --- | --- |
| 首次加载 | 稳定占位和“加载中”，避免假零值 |
| 刷新中 | 可保留上次数据，同时标明刷新状态和原时间 |
| 空结果 | 说明当前场站/时间范围无数据；有适用操作时提供调整筛选入口 |
| 请求失败 | 可理解的原因与重试入口；保留旧数据时明确标为旧数据 |
| 部分失败 | 对应分区独立说明，不把其他有效数据一并清空 |
| 无权限 | 明确权限状态，不伪装为无数据 |

新建或改动组件以普通文本对比度至少 4.5:1、大字号文本至少 3:1 为验收目标；用于识别控件、焦点和关键图形的颜色至少 3:1。装饰性面板边框无需加粗到同样标准。主题 token 本身不等于对比度合格，尤其检查次要文字、蓝底白字和浅色选中态；必要时使用组件专属前景色，保留背景基准。

支持键盘操作；不能将核心信息仅放在 hover。动效默认 150–200ms，避免持续闪烁；尊重 `prefers-reduced-motion`，降低或停止非必要动画。静态 Mock 的 Tabs、筛选、详情与主题切换要在本地真实响应，模拟数据标识清楚。

## 9. 主题维护与验收

M1/M2 沿用 `dashboard-theme` 本地偏好和现有初始化行为。图表、弹窗、Tooltip、表单同主页面一起切换，不能只改页面底色。

修改共用 CSS 后，按[主题维护说明](../shared/styles/README.md)同步以下两个实际入口的 `style#vifa-m3-theme`，维持单文件部署：

- [M1 页面](../m1/web/dashboard_energy.html)
- [M2 页面](../m2/web/场站三条能效链路能流图.html)

页面实现发生变化时，至少执行以下检查并仅报告实际结果：

- [ ] 明暗两种主题，桌面 1440px、平板 834px、手机 390px 查看实际渲染；新增布局补查 320px 窄屏。
- [ ] M1/M2 与 M3 的渐变、面板底色、边框和阴影视觉一致，不仅比较变量。
- [ ] 标题、单位、长设备名、图例可读；无页面级横向溢出，局部滚动可用。
- [ ] 主操作、选中态、禁用态、键盘焦点在明暗主题均可辨认。
- [ ] 主题切换、筛选、历史查询、详情等受影响交互正常；覆盖相关加载、空态与失败状态。
- [ ] 检查所改组件关键前景/背景组合的对比度；保留原有数据、时区与业务语义。
- [ ] 如改共用主题，确认两个 HTML 内嵌 CSS 与主题源一致。

纯文档变更检查路径、token 与规则一致性即可；不据此声称页面已通过视觉或交互验收。业务逻辑变化另按项目流程执行相关验证。

## 10. 任务提示范例

> 按 docs/DESIGN.md 优化指定 VIFA 页面。先读取页面和共用主题，沿用 M3 背景基准，根据页面用途设计清晰的排版和交互强调色。保留数据逻辑、时间展示和历史查询；补齐此次涉及组件的状态。完成后检查明暗模式及桌面、平板、手机实际渲染，报告修改与实际验证结果。

结构参考：[VoltAgent awesome-design-md](https://github.com/VoltAgent/awesome-design-md/tree/main)。借鉴其主题、颜色、字体、组件、布局、响应式和提示指南的组织方式；VIFA 的具体规则来自本项目约定与源码，不采用其他品牌的视觉身份。
