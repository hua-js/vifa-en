# 场站三条能效链路历史曲线与瓶颈事件设计

日期：2026-08-25\
状态：设计已确认，尚未实施

## 1. 背景与目标

现有 HTML 已展示三条链路的瞬时效率：

- 光→储；
- 储→用；
- 光→用。

本设计在不改变现有实时链路计算的前提下，增加两项能力：

1. 每分钟保存一次三条链路的计算结果，供页面展示“当日 00:00 至最新分钟”的效率曲线；
2. 根据可配置规则识别并记录瓶颈事件，当前只包含“逆变器低负载”和“电池温升”。

页面刷新只读取结果，不触发写入。分钟结果由独立的定时计算流程生成并使用幂等写入。

## 2. 范围

### 2.1 本阶段包含

- 三条链路分钟效率点的数据模型；
- 每场站一份瓶颈规则配置；
- 两类瓶颈事件的数据模型与状态机；
- 当日效率曲线、当日累计效率和事件列表的逻辑 API 契约；
- 现有 HTML 适配分钟曲线时所需的行为调整；
- 唯一约束、索引、幂等和缺失分钟处理规则。

### 2.2 本阶段不包含

- 修改 `m2/station_energy_backend.py`；
- 修改现有 HTML；
- 创建真实 NocoBase 集合或编写迁移；
- 确定 NocoBase REST API 的 URL、鉴权、分页和原始字段映射；
- 绝对高温、电池压差、设备离线、字段质量等其他瓶颈规则；
- `good`、`missing`、`stale`、`bad` 等字段级数据质量状态；
- 自动删除历史数据。数据保留周期由后续运维策略管理，本设计的数据表不主动清理记录。

## 3. 已确认的核心决策

| 项目 | 决策 |
|---|---|
| 保存粒度 | 每分钟一个时间桶 |
| 曲线范围 | 场站本地自然日 00:00 至当日最新分钟 |
| 横轴 | 固定显示 00:00—24:00，未来时段留空 |
| 缺失数据 | 保留缺口，不补零、不插值 |
| 写入时机 | 定时计算流程写入，页面刷新只查询 |
| 重复分钟 | 按场站和分钟执行 Upsert |
| 规则配置 | 所有阈值、窗口、触发时长和恢复时长均可配置，不在程序中硬编码业务默认值 |
| 瓶颈类型 | 逆变器低负载、电池温升 |
| 事件保存 | 只保存 `active` 和 `recovered` 事件，候选状态由历史窗口即时重建 |
| 当日累计效率 | 按有效分钟的累计输入、输出计算，不取分钟效率的算术平均值 |

## 4. 方案选择

### 4.1 采用：分钟明细表、规则表、事件表

使用三张 NocoBase 集合分别保存分钟效率、场站规则和瓶颈事件。该方案支持单分钟幂等更新、任意时间范围查询、独立规则维护和事件生命周期查询。

### 4.2 未采用：每日一行 JSON

把 1440 个点写入每日 JSON 会造成并发覆盖、局部更新困难、单点补算成本高，也不利于建立时间索引。

### 4.3 未采用：页面查询时临时计算全天曲线

原始设备功率分散在不同表中，查询时临时聚合会让页面响应依赖多个数据源，并重复执行相同计算。分钟结果持久化可以把采集、计算和展示解耦。

## 5. 总体架构

```text
现有各设备原始数据表
    ↓ 按场站、设备、分钟读取并转换成统一逻辑输入
每分钟定时计算流程
    ├─ 计算三条链路瞬时效率及对应输入/输出功率
    │      ↓ Upsert
    │  station_efficiency_points
    │
    └─ 读取规则和所需回看窗口，重建连续条件
           ↓ 打开、更新或关闭事件
       efficiency_bottleneck_events

HTML 查询流程
    ↓
读取当日分钟点 + 当日累计效率 + 与当日重叠的事件
    ↓
绘制实时链路、今日效率曲线和瓶颈事件
```

各设备原始功率不要求位于同一张表。未来的数据访问适配层负责把不同设备表的字段、单位、方向和时间转换成统一逻辑输入。三张新集合不复制全部设备原始数据。

瓶颈候选状态不单独落表。每次分钟任务从现有设备数据源读取足够的历史窗口，重新判断连续触发或连续恢复，因此服务重启不会依赖进程内计数器。

## 6. 时间规则

- 所有持久化时间字段使用带时区时间类型；在 PostgreSQL 中对应 `timestamp with time zone`。
- `data_time` 表示一分钟时间桶的起点，例如 `14:36:00`，秒和微秒必须归零。
- 自然日按场站配置的时区计算；当前页面契约示例使用 `Asia/Shanghai`。
- 数据库存储和比较使用绝对时间，API 输出使用带偏移量的 ISO 8601 字符串。
- 当日查询范围采用左闭右开区间 `[day_start, next_day_start)`，避免 24:00 重复归属两天。
- 定时任务漏跑或原始数据缺失时不创建虚假分钟，不使用前值填充，也不插值。
- 若后续具备历史原始数据，可按相同公式补算缺失分钟；补算仍使用相同唯一键 Upsert。

## 7. 集合一：分钟效率点

集合名：`station_efficiency_points`

每行表示一个场站在一个分钟时间桶内的三条链路计算结果。

| 字段 | 建议类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | bigint | 否 | 主键 |
| `station_id` | relation / bigint | 否 | 关联场站 |
| `data_time` | timezone-aware datetime | 否 | 分钟桶起点 |
| `pv_storage_efficiency` | decimal | 是 | 光→储瞬时效率，百分比 |
| `storage_load_efficiency` | decimal | 是 | 储→用瞬时效率，百分比 |
| `pv_load_efficiency` | decimal | 是 | 光→用瞬时效率，百分比 |
| `pv_storage_input_kw` | decimal | 是 | 光→储输入功率 |
| `pv_storage_output_kw` | decimal | 是 | 光→储输出功率 |
| `storage_load_input_kw` | decimal | 是 | 储→用输入功率 |
| `storage_load_output_kw` | decimal | 是 | 储→用输出功率 |
| `pv_load_input_kw` | decimal | 是 | 光→用输入功率 |
| `pv_load_output_kw` | decimal | 是 | 光→用输出功率 |
| `formula_version` | text | 否 | 计算公式版本 |
| `calculated_at` | timezone-aware datetime | 否 | 实际完成计算的时间 |

### 7.1 约束和索引

- 主键：`id`；
- 唯一约束：`(station_id, data_time)`；
- 复合索引：`(station_id, data_time)`，服务于按场站和时间范围查询；
- `station_id` 的外键列应有索引；
- 写入使用 `(station_id, data_time)` 作为冲突目标执行 Upsert。

唯一约束是幂等性的最终保障。同一分钟被重复执行、补算或重试时更新原行，不产生第二个点。

### 7.2 空值语义

三条链路独立判断。某条链路无法计算时，该链路的效率以及无法确认的输入/输出字段保存为 `null`，其他可计算链路仍正常保存。`null` 不转换为 `0`。

效率为 `0` 只表示输入和输出值完整且公式确实得到零效率，不表示缺失或异常。

### 7.3 数据量

每个场站每天最多 1440 行，每年约 525,600 行。按 `(station_id, data_time)` 查询单日数据时最多返回 1440 行。

## 8. 集合二：瓶颈规则配置

集合名：`efficiency_bottleneck_rules`

当前每个场站保存一行规则。

| 字段 | 建议类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | bigint | 否 | 主键 |
| `station_id` | relation / bigint | 否 | 关联场站，一场站一行 |
| `enabled` | boolean | 否 | 是否启用瓶颈识别 |
| `inverter_min_running_power_kw` | decimal | 否 | 逆变器参与低负载判断的最小运行功率 |
| `inverter_low_load_threshold_pct` | decimal | 否 | 低负载率阈值 |
| `inverter_trigger_minutes` | integer | 否 | 连续满足多少分钟后触发 |
| `inverter_recovery_minutes` | integer | 否 | 连续不满足低负载多少分钟后恢复 |
| `temperature_rise_window_minutes` | integer | 否 | 温升比较窗口 |
| `temperature_rise_threshold_c` | decimal | 否 | 窗口温升阈值 |
| `temperature_trigger_minutes` | integer | 否 | 连续满足多少分钟后触发 |
| `temperature_recovery_minutes` | integer | 否 | 连续低于温升阈值多少分钟后恢复 |
| `version` | integer | 否 | 规则版本，每次业务配置变更递增 |
| `updated_at` | timezone-aware datetime | 否 | 更新时间 |

### 8.1 约束

- `station_id` 唯一；
- 所有分钟数字段必须为正整数；
- 两个功率或温升阈值必须为非负数；
- 低负载率阈值必须处于业务允许的百分比范围；
- 配置保存前完成上述校验，不能依赖计算任务静默修正无效配置。

程序不内置业务默认阈值。新场站必须先创建有效配置；没有配置或 `enabled=false` 时仍保存分钟效率，但不打开新瓶颈事件。

规则变更后，新事件使用新版本。已经打开的事件继续使用打开时记录的阈值和规则版本，直至恢复，避免同一事件中途改变判定口径。完整规则快照保存在事件的 `evidence` 中。

## 9. 集合三：瓶颈事件

集合名：`efficiency_bottleneck_events`

| 字段 | 建议类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | bigint | 否 | 主键 |
| `station_id` | relation / bigint | 否 | 关联场站 |
| `event_type` | text / enum | 否 | `inverter_low_load` 或 `battery_temperature_rise` |
| `device_id` | text | 否 | 源设备唯一标识 |
| `device_name` | text | 否 | 页面展示名称 |
| `start_time` | timezone-aware datetime | 否 | 首个满足触发条件的分钟 |
| `end_time` | timezone-aware datetime | 是 | 首个满足恢复条件的分钟；持续中为空 |
| `last_seen_time` | timezone-aware datetime | 否 | 最近一次有效评估时间 |
| `status` | text / enum | 否 | `active` 或 `recovered` |
| `observed_value` | decimal | 否 | 本事件中最不利观测值 |
| `threshold_value` | decimal | 否 | 打开事件时使用的阈值 |
| `observed_unit` | text / enum | 否 | `%` 或 `℃` |
| `evidence` | JSON | 否 | 持续时间、规则快照及关键观测值 |
| `impact_chain` | JSON / text array | 否 | 受影响链路 |
| `rule_version` | integer | 否 | 打开事件时的规则版本 |

### 9.1 约束和索引

- 复合索引：`(station_id, start_time)`；
- 复合索引：`(station_id, status)`；
- `station_id` 的外键列应有索引；
- 幂等唯一键：`(station_id, event_type, device_id, start_time)`；
- 同一场站、事件类型和设备最多存在一个 `active` 事件。

若底层 PostgreSQL 可直接管理索引，建议增加仅覆盖 `status='active'` 的部分唯一索引：

```sql
create unique index efficiency_bottleneck_events_one_active
on efficiency_bottleneck_events (station_id, event_type, device_id)
where status = 'active';
```

如果 NocoBase 的集合配置界面不能创建部分唯一索引，则由事件写入服务在同一事务中查询并锁定现有活动事件，再执行打开或更新；数据库侧仍保留事件幂等唯一键。

### 9.2 观测值口径

- 逆变器低负载事件的 `observed_value` 保存事件期间最低负载率；
- 电池温升事件的 `observed_value` 保存事件期间最大窗口温升；
- `threshold_value` 和 `rule_version` 在事件打开后不改变；
- `last_seen_time` 在每次得到该设备的有效判定结果时更新；
- `evidence` 保存最新状态、最不利状态、连续分钟数和打开时规则快照，供页面解释原因。

## 10. 分钟处理流程

每个场站的定时任务按以下顺序执行：

1. 确定当前场站时区和需要处理的分钟桶；
2. 从现有各设备表读取该分钟所需的原始数据；
3. 由数据适配层统一字段、单位、方向和设备标识；
4. 计算三条链路的效率、输入功率和输出功率；
5. Upsert 一行 `station_efficiency_points`；
6. 读取当前有效的场站规则；
7. 从现有设备表读取足够的历史回看窗口，重建连续触发或恢复条件；
8. 对每个设备打开、更新或关闭对应事件；
9. 提交事务并记录任务运行日志。

步骤 5 的分钟结果和步骤 8 的事件处理应设计为可重试操作。重复处理同一分钟不得生成重复分钟点或重复事件。

## 11. 通用事件状态机

```text
正常
  ↓ 连续满足触发条件达到 trigger_minutes
持续中（active）
  ↓ 连续满足恢复条件达到 recovery_minutes
已恢复（recovered）
```

触发候选和恢复候选只属于计算过程，不作为独立事件行保存。每次执行根据历史窗口重新构造连续分钟数。

通用规则：

- 触发后，`start_time` 取连续触发序列的第一个分钟，而不是达到时长的最后一分钟；
- 恢复后，`end_time` 取连续恢复序列的第一个分钟；
- 缺失分钟不计入触发或恢复连续时长，也不自动关闭活动事件；
- 连续判断要求相邻有效样本的分钟桶连续，时间断档会中断候选序列；
- 事件跨越午夜时仍为同一事件，不在 00:00 拆分；
- 相同事件被重复计算时使用事件唯一键更新，不新增重复行。

## 12. 逆变器低负载规则

### 12.1 输入

- `station_id`；
- `device_id`、`device_name`；
- `data_time`；
- `active_power_kw`；
- `rated_power_kw`。

额定功率必须为正数。负载率计算如下：

```text
load_rate_pct = active_power_kw / rated_power_kw × 100
```

### 12.2 触发

一个分钟同时满足以下条件时记为低负载分钟：

```text
active_power_kw >= inverter_min_running_power_kw
且
load_rate_pct < inverter_low_load_threshold_pct
```

连续低负载分钟达到 `inverter_trigger_minutes` 后打开事件。夜间停机或功率低于最小运行功率时不触发低负载事件。

事件影响链路为“光→储”和“光→用”。证据至少包含当前负载率、最低负载率、额定功率、阈值、连续分钟数和规则快照。

### 12.3 持续和恢复

事件持续期间，每个有效分钟更新 `last_seen_time`，并在出现更低负载率时更新 `observed_value`。

有效记录连续不再满足低负载条件达到 `inverter_recovery_minutes` 后关闭事件。“不再满足”包括负载率达到阈值，或设备功率低于最小运行功率而退出运行判断区间。原始记录缺失不计为恢复。

## 13. 电池温升规则

### 13.1 输入

- `station_id`；
- `device_id`、`device_name`；
- `data_time`；
- `temperature_c`。

对每个设备独立计算窗口温升：

```text
temperature_rise_c = 当前分钟温度 - 窗口起点分钟温度
```

窗口长度由 `temperature_rise_window_minutes` 配置。窗口起点必须有对应的有效分钟记录；窗口内出现断档时，该分钟不形成有效温升判断。

### 13.2 触发

当下式连续满足 `temperature_trigger_minutes` 时打开事件：

```text
temperature_rise_c >= temperature_rise_threshold_c
```

本规则只判断温升速度，不判断绝对高温。

事件影响链路为“光→储”和“储→用”。证据至少包含当前温度、窗口起点温度、窗口分钟数、最大温升、阈值、连续分钟数和规则快照。

### 13.3 持续和恢复

事件持续期间，每个有效分钟更新 `last_seen_time`，并在出现更大温升时更新 `observed_value`。

窗口温升连续低于阈值达到 `temperature_recovery_minutes` 后关闭事件。温度记录或窗口起点记录缺失时不计为恢复。

## 14. 当日累计效率

`summary_today` 不能对分钟效率直接取平均。每条链路独立使用当日有效分钟的累计输入和累计输出：

```text
minute_input_kwh  = input_kw  × 60秒 / 3600
minute_output_kwh = output_kw × 60秒 / 3600

today_efficiency_pct =
    Σ minute_output_kwh / Σ minute_input_kwh × 100
```

只有该链路输入和输出都有效的分钟才进入该链路累计。缺失分钟被排除，不补零。累计输入为零时，该链路当日效率返回 `null`。

一分钟固定采样下，功率乘以相同的 `1/60` 系数不会改变最终比值，但接口实现仍应使用“累计能量”的语义，便于未来支持非固定间隔。

```json
        "device": "1#光伏逆变器",
        "start": "2026-08-25T13:20:00+08:00",
        "end": null,
        "evidence": "负载率 12.4%，低于配置阈值并持续 10 分钟",
        "impact": ["光→储", "光→用"],
        "status": "持续中"
      }
    ]
  }
}
```

### 15.1 `range`

- `start_time` 是场站本地当日 00:00；
- `end_time` 是下一日 00:00；
- `latest_time` 是当日已保存分钟点中的最大 `data_time`；
- 当日没有分钟点时，`latest_time` 为 `null`；
- `interval_seconds` 当前固定为 60。

### 15.2 `trend`

- 查询条件为 `station_id` 相等且 `data_time` 位于 `[start_time, end_time)`；
- 最多 1440 个元素，按 `data_time` 升序；
- 不返回未来分钟，也不补齐缺失分钟；
- 三条链路分别允许为 `null`，一条链路为空不影响另两条；
- 响应不得把 `null` 转换为零。

### 15.3 `events`

事件按“与当日时间窗重叠”查询：

```text
start_time < day_end
且
(end_time is null 或 end_time >= day_start)
```

因此前一日开始、当日仍持续的事件会显示。接口负责把数据库枚举值映射为页面中文文案；持续中事件的 `end` 为 `null`。

### 15.4 空结果与错误

- 当日没有分钟点时返回空 `trend`，三条 `summary_today` 效率均为 `null`，不伪造 0 点；
- 当日没有重叠事件时返回空 `events`；
- 单条链路没有有效累计输入时只将该链路汇总设为 `null`；
- 请求参数或场站不存在时返回结构化错误，不能回退为模拟数据；
- 错误响应不得包含数据库凭据、NocoBase 令牌或完整授权头。

## 16. HTML 调整要求

现有三条实时能流链路保持不变。曲线和事件区域按以下规则调整：

- 删除对 `data.trend.length === 25` 的固定要求；
- 删除对 `row.hour` 的依赖和整点取整逻辑；
- 根据 `data_time` 相对 `range.start_time`、`range.end_time` 的比例计算横坐标；
- 横轴刻度仍显示 0、4、8、12、16、20、24 时；
- 曲线只绘制到 `latest_time`，未来区域保持空白；
- 相邻有效点间隔超过 120 秒时断开折线，不跨缺口连线；
- 同一链路的 `null` 点断线，另外两条链路继续独立绘制；
- 提示框按鼠标位置寻找最近的实际分钟点；
- 活动事件绘制到 `latest_time`，已恢复事件绘制到 `end`；
- 跨日事件在当日横轴边界处裁剪显示，不修改其真实开始或结束时间。

页面文案调整：

| 原文案 | 新文案 |
|---|---|
| `24小时链路效率` | `今日链路效率` |
| `24h输入、输出电量累计` | `今日输入、输出电量累计` |
| 无事件空状态 | `当前时间范围内无瓶颈事件` |

## 17. 权限与运行边界

- 分钟任务使用仅能读取所需设备表、读取规则表、写入分钟点和事件表的服务账号；
- iframe 页面只通过后端查询聚合结果，不持有具有写权限的 NocoBase 令牌；
- 规则修改权限与看板读取权限分离；
- 对 `station_id` 实施与 NocoBase 用户或租户一致的访问控制，禁止通过改请求参数读取其他场站；
- 写入和事件状态切换保留运行日志，但日志不记录凭据。

## 18. 验收标准

### 18.1 分钟点

- 同一场站同一分钟重复执行后只有一行；
- 14:36 打开页面时，曲线只包含 00:00 至 14:36 的已有分钟；
- 14:37 没有数据时不生成 0 值或复制 14:36；
- 单条链路为 `null` 时，其他链路仍正常返回；
- 超过 120 秒的点间隔在页面上形成断线；
- 当日累计效率由累计输入和输出得到，不等于分钟效率的简单平均值。

### 18.2 逆变器低负载

- 低于最小运行功率的停机时段不会打开事件；
- 连续低负载达到配置时长后只打开一个事件；
- 事件开始时间为连续序列首分钟；
- 持续期间记录最低负载率；
- 连续恢复达到配置时长后关闭，结束时间为恢复序列首分钟；
- 缺失记录不会误触发或误恢复。

### 18.3 电池温升

- 使用配置窗口计算温升，不使用绝对温度替代；
- 连续满足配置时长后只打开一个事件；
- 持续期间记录最大窗口温升；
- 连续恢复达到配置时长后关闭；
- 窗口数据不完整时不形成有效判断。

### 18.4 页面与跨日

- 横轴固定为自然日 00:00—24:00，最新点之后为空白；
- 活动事件显示到 `latest_time`；
- 前一日开始且当日仍持续的事件可见，并在 00:00 边界裁剪；
- 事件跨午夜不拆成两行；
- 无点和无事件时分别显示正确空状态，不使用模拟数据。

7. 通过单元测试、数据库约束测试和浏览器端到端验收。
