# M2 效率曲线与瓶颈历史查询

更新日期：2026-09-07。仓库实现已完成，未在生产环境部署或联调。

## 页面使用

- 效率曲线：选择日期后点击「查询」，或使用「前一天」「后一天」「回到今日」。历史曲线固定展示北京时间 00:00–24:00；分钟缺失或链路未运行时保留断点，不补零。历史日期下显示该日累计效率，仍按有效分钟累计输出/输入计算，不对效率取算术平均。
- 效率瓶颈：「曲线当日」显示与上方曲线同一天的事件；「历史记录」支持日期范围、近7天/近30天、类型与最新状态筛选，每页10条。日期范围含起止两天，单次最多31天，不限制只能查看最近31天。
- 历史记录显示完整开始时间和恢复时间；「查看曲线」打开事件开始当天。若事件早于查询范围开始，打开查询范围第一天。跨日事件保留一个完整生命周期，状态为当前已保存的最新状态，不是历史时刻的状态快照。
- 电站切换重新查询所选日期与日期范围。实时自动刷新不会覆盖已选历史曲线或历史事件；失败、超时与空结果分别提示。
- 历史表在窄屏中可左右滚动，查看完整判定数据、影响链路及曲线入口。

## 只读接口

沿用 `GET /energy-efficiency-api`，默认查询行为保持不变。

| 操作 | 查询参数 | CLI |
|---|---|---|
| 实时看板 | `station_id=ES02` | `dashboard ES02` |
| 单日效率历史 | `operation=history&station_id=ES02&date=2026-09-06` | `history ES02 2026-09-06` |
| 瓶颈历史 | `operation=events&station_id=ES02&start_date=2026-09-01&end_date=2026-09-06` | `events ES02 2026-09-01 2026-09-06` |

- 历史读取直接访问既有 `t_efficiency_points`、`t_efficiency_bottleneck_events`，不读取实时设备源，不触发计算、写入或清理。
- `history` 返回 `operation`、`station_id`、`range`、`summary`、`trend`、`events`。当日最多1440个分钟点；查询今天时仅返回截至查询时间的记录。`range.cutoff_time` 表示事件阴影截止时间，完整历史日到次日00:00。
- `events` 返回 `operation`、`station_id`、`range`、`events`。Node-RED 与 Python 均校验日期、未来日期、顺序和31天范围。前端对所查区间完整事件列表做类型、状态筛选与分页。
- 日期参数为 `YYYY-MM-DD`；数据库读取使用北京时间自然日转绝对时间的区间 `[start, next_day_after_end)`。事件按 `start_time < range_end` 且「活动中，或已恢复且 `end_time >= range_start`」查询，包含在查询范围之后才恢复的跨日事件。
- Node-RED 对 HTTP 操作做只读白名单校验，`minute`、`cleanup` 不通过该 HTTP 查询入口开放。

## 部署文件与验证

需一并更新 `m2/web/场站三条能效链路能流图.html`、`m2/energy-efficiency-api.py`、`m2/station_efficiency_history.py`、`m2/station_efficiency_nocobase.py` 和 `m2/node_red/node-red-energy-efficiency-api-flow.json`。Flow 的「执行能效计算脚本」固定命令不再带 `dashboard`；操作由「检查场站」校验后一起传入，两个节点必须同时更新。

没有新增表、迁移、采集规则或历史补算。可查询的记录取决于既有分钟任务已保存的数据；未采集日期显示空记录。历史读取无需实时设备源凭据，但仍需既有 NocoBase 只读配置和权限。

本地验证命令：

```sh
python3 -m unittest discover -s m2/tests -t . -q
node m2/tests/energy_dashboard_e2e.js
node m2/tests/efficiency_history_e2e.js
```

浏览器验证使用本地模拟响应，覆盖正常/空/失败结果、范围校验、分页筛选、事件跳转、切站隔离、过期请求、实时刷新以及320/390/768/1440px和深色主题；尚未用真实 NocoBase 历史数据验证。
