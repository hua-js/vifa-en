# M1 常驻接口部署

## 范围与实现

M1使用`m1/resident_api.py`常驻API进程，内部监听`127.0.0.1:8811`，Node-RED保留`/dashboard_energy_api`公网入口。不是每次`docker exec`启动一个新Python；模块和私有能源配置只在服务启动时加载。

每次请求使用当前用户凭据并发读取固定场站及电站，再依次读取依赖节点和实时记录。权限与客户拓扑全部校验完成后，并行读取两站负载及柜体/光伏表数据；生产于2026-10-22 12:11更新为`m1-pv-controller-summary-v2`，两站光伏均读取工控机汇总（emu13/emu27），采集时间各取自身`last_time_iso`，不再请求Growatt。不缓存完成业务响应，不跨用户复用数据，保持客户与设备白名单隔离；字段及告警口径见[时间与历史告警](时间与历史告警说明.md)。最多同时处理4个业务请求；无凭据及超容量请求不读取上游。

原`m1/dashboard_energy_api.py` CLI及直接脚本入口保留，默认继续不启用连接池；常驻入口启用每请求独立连接池，用于隔离用户与传输状态。常驻服务不使用内置默认用户Token；能源凭据复用生产私有配置。鉴权失败返回业务提示，不泄露源响应或令牌。

## 文件与隔离

- 镜像：`m1/deploy/Dockerfile`，基底固定已验证的Python3.12生产镜像，覆盖M1源码并替换entrypoint，**不运行基底中的M3/M4服务**。
- 独立Compose：`m1/deploy/compose.yaml`，项目`vifa-m1-api`。使用`M1_API_IMAGE`，不改共享`RUNTIME_IMAGE`、M2独立镜像或M3/PV/M4 Compose。
- `M1_DEPLOYMENT_ROOT`指向实际部署目录；项目及能源配置只读挂载，原`runtime/m1`挂载为`/state`，保留已有告警SQLite，不重建数据库。
- UID/GID10001，host网络、只读根、cap-drop、no-new-privileges和`/dev/mqueue` tmpfs保持。业务端口只绑定loopback，不增加公网端口。
- 配置或能源凭据轮换后需明确重启M1服务；本服务不启动定时采集、预测或设备控制任务。

## 验证边界与回退

`/ready`只说明M1配置和HTTP进程就绪，不代表EMS用户凭据有效或全部数据源成功。内置默认M1凭据已过期，不能把它的失败请求算作正常加载耗时；缺少有效EMS当前用户凭据时，应明确说明成功请求尚未闭环。

回退先恢复此次备份的Flow并重载Node-RED，公网恢复原exec→`m1-launcher.py`链路，再停止独立M1服务。原共享镜像、启动器、私有配置和历史目录不删除、不改动。服务原生响应与健康接口不触发预测或设备动作；正常授权看板请求继续按原逻辑保存告警历史。

发布证据归`outputs/m1/releases/`，测试归`outputs/m1/tests/`。实际镜像、备份位置、耗时及生产验证状态在发布完成后记录，不用历史通过结果代替当前验证。

## 响应压缩与加载优化（2026-10-22已部署）

北京时间11:48以管理API的`nodes`方式仅更新M1响应Function `1a99b852d2815bcc`。Node-RED现有`functionExternalModules=true`允许使用Node内置`zlib`；仅为该节点注册`m1Zlib`，未安装npm依赖或更改全局配置。后端镜像仍为上节`8f248f627738…`，正式HTML保持，六个常驻容器未重启，其他105个节点逐项保持，M4自动/电站2写表均1。

### 原因与实现

- 慢样本并非固定17.9秒：此前公网重复请求为2.221、18.271及14.610秒，链路存在波动。未优化时，每次响应包含最近1000条历史告警，约390KB；即使请求gzip仍无`Content-Encoding`，慢样本响应体下载约7秒。工控机本地完整M1/Node-RED接口约4.35/3.88秒，真实能源源三组1.88/1.24/1.27秒，SQLite约1290条历史扫描解码0.132秒；这些证据不能把17.9秒归因于新光伏或数据库扫描。
- M1在完整业务封装及鉴权结果保留后，按`Accept-Encoding`协商标准gzip。仅压缩至少1024字节且确实变小的响应，保留`no-store`并设置`Vary: Accept-Encoding`。不支持gzip、显式`gzip;q=0`及小响应沿用原JSON；压缩失败保留原有效响应，日志只记规范化状态，不记录凭据或业务内容。
- 数据范围、实时取源、告警记录、历史总数与1000条返回限制均保持，不引入跨用户缓存。独立服务器进程实测真实JSON 389554字节压缩至22117字节，减少94.32%，解压后SHA完全一致；候选函数试跑约24～47毫秒。生产gzip请求已确认返回完整1000条历史及emu13光伏节点。
