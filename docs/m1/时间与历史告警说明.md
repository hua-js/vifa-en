# M1 柜体时间与历史告警

当前页面入口为 `m1/web/dashboard_energy.html`（唯一维护入口）；服务端为 `m1/dashboard_energy_api.py`。部署时同时替换实际使用的 HTML 和 Python 文件，既有 `/dashboard_energy_api` 路由与 JSON 顶层结构不变，无需增加第三方依赖。

## 柜体时间

- 每个储能柜显示自己的 `t_emu.last_time_iso`，响应字段为 `realtime[].cabinet_timestamp`，精确到秒，统一北京时间。
- 所有卡片统一标为“采集时间”。柜体源时间不可用时，展示已有 `en_realtime.timestamp`；两者都缺失时显示“暂无采集时间”。
- 光伏计量表显示电站 2 储能柜中最新的有效采集时间：前端筛选同电站非聚合储能柜，逐柜优先取 `cabinet_timestamp`、缺失时取 `timestamp`，再取最新时间；无有效时间时显示“暂无采集时间”。此显示规则仅需更新前端，不依赖 `pv_meter_timestamp`，也不使用逆变器或页面刷新时间。其他光伏计量表仍使用对应实时数据时间。
- 后端仍提供 `emu27.last_time_iso` 对应的 `pv_meter_timestamp`，当前页面不使用该字段。`emu27` 不参与储能功率求和；光伏功率和效率仍沿用原来的 9 台逆变器汇总。
- 同站其他柜缺失或功率无效时，仍保留已取得的单柜时间；聚合功率继续按原规则置空。原有功率、SOC 与在线状态的来源和判定不变。

## 历史告警

- 历史记录由服务端 SQLite 持久化，默认文件为 仓库根目录的 `runtime/m1/alert_history.sqlite3`。支持环境变量 `M1_ALERT_HISTORY_DB` 或 CLI 参数 `--history-db /持久化目录/alert_history.sqlite3`；CLI 优先。既有部署如使用旧数据库路径，需保留显式路径配置；本地整理不修改服务器安装位置。
- 部署账号需对文件及父目录有读写权限；容器运行需挂载持久化目录。更新代码时保留该目录，多个执行进程需指向同一文件。文件不应放入对外提供静态文件的目录。
- 每次既有看板请求执行 Python 时，将本次检出的三类告警保存。相同场站、告警标识、采集时间只保存一次，后续采集时间的异常另记一条。此处是异常采样记录，不合并为生命周期事件，也不推断已恢复、持续中或处置状态。
- 历史在页面关闭、重开或服务重启后保留；没有页面刷新或其他调用时，当前 CLI 不会自行采集。仓库原 M1 没有历史告警存储，本次无法补回启用前及未采集期间的记录。
- 接口新增 `data.alert_history`，包含 `status`、`records`、`total`、`limit`、`first_recorded_at`。默认响应最近 1000 条，旧记录仍保留在库中；页面按北京时间日期、类别、设备关键字和电站筛选这 1000 条，每页 20 条。当前告警和 KPI 继续仅使用 `data.alerts`。
- 历史告警同时校验目标场站 ID、ES01/ES02 电站归属及设备节点 ID。其他场站、同场站 ID 下非本拓扑设备、设备归属缺失的记录不展示、不计入总数，也不占最近 1000 条额度；旧库原始记录保留。拓扑节点已移除的历史记录同样不显示。此修复需同时更新 HTML 和 Python。
- 日期默认填入北京时间最近 7 个自然日（含今天）；清除筛选时恢复该范围。手动选定的日期在自动刷新和告警模式切换时保留。
- 记录字段沿用当前告警，增加 `recorded_at` 入库时间；页面展示 `start_time` 实际采集时间。存储失败单独返回 `alert_history.status=error` 并显示提示，不阻断实时看板，不把失败显示成没有历史记录。
