# M3 储能功率驱动 SOC 预测设计

日期：2026-09-02
状态：已确认设计，待实施计划

## 背景

M3 当前将 `storage_soc` 当作普通单变量时间序列，使用
SeasonalNaive、AutoETS、AutoARIMA 或 MSTL 直接预测 SOC。两座电站的 SOC
预测 MAPE 仍然偏高。现有实现还有两项口径不一致：自定义预测会将模型输出锚定到
最后一个真实 SOC，而定时预测没有相同处理；交叉验证评分使用未锚定预测，和最终发布
值不一致。

原始 `t_es_data:list` 已包含储能功率字段 `latest_power`。该字段单位为 kW，负值表示
充电，正值表示放电；目前 M3 只读取 `load_power` 和 `emus_soc`，没有将
`latest_power` 送入 SOC 训练和预测。未来 EMS 计划不可用，只有历史与实时功率。
现场运行规律为周一至周六基本相同，周日使用不同的充放电计划。两座电站的铭牌容量、
实际可用容量和运行 SOC 上下限暂不明确。

## 目标

- 用现有 `latest_power` 建立功率驱动的 SOC 预测。
- 定时 15 分钟、未来 24 小时预测与自定义 30 秒至 1 小时、未来 1 至 7 天预测共用
  同一个 SOC 核心。
- 废止所有直接对 SOC 做单变量预测的旧策略。
- 为两座电站独立构造功率模板、辨识功率到 SOC 变化的关系并独立选冠军。
- 保留现有负载预测、两条对外序列、API 和数据库表结构。
- 以 SOC MAE（百分点）为选模主指标，以 P90 绝对误差为次指标，继续展示 MAPE。
- 新模型必须在无未来数据泄漏的回测中优于最后值基线后才可正常发布。

## 非目标

- 不引入新的外部数据源。
- 不要求提前提供电池容量、效率或运行 SOC 上下限。
- 不预测或展示第三条储能功率业务序列。
- 不修改负载预测策略。
- 不重算历史任务，不将旧策略结果纳入新策略性能汇总。
- 第一版不学习或猜测现场的充放电停止 SOC，只执行 0 至 100 的物理边界。

## 总体架构

```text
t_es_data 原始记录
    │
    ├─ load_power ───────────────→ 现有负载预测（不变）
    │
    ├─ emus_soc ───────┐
    └─ latest_power ───┴─→ 统一 SOC 核心
                              │
                              ├─ 周一至周六 / 周日功率模板
                              ├─ SocPowerStateModel
                              ├─ AutoARIMAX
                              ├─ 公平滚动回测与冠军选择
                              └─ 最后值降级
                                      │
                                      └─ storage_soc 对外序列
```

定时路径和自定义路径保留各自的任务调度、时间粒度、预测时长和持久化流程。两条路径
只共享数据规范化之后的 SOC 训练、预测、后处理和选模核心，避免再次产生选模、回测与
线上输出不一致。

## 数据契约

### 原始字段

每条原始记录至少涉及：

- `es_sn`：完整电站标识；
- `timestamp`：源时间；
- `emus_soc`：SOC，合法范围为 0 至 100；
- `latest_power`：储能功率，单位 kW，负值充电、正值放电；
- `load_power`：现有负载字段，处理不变。

M3 增加内部 `StationForecastInputs`，一次原始读取同时生成现有负载/SOC 实绩点和
SOC 功率特征。`latest_power` 不加入公开 `SERIES_IDS`，不写成第三条预测序列。

### 时间桶

- `emus_soc` 继续取桶内最后一个及时、合法的真实值。
- `latest_power` 使用桶内有效样本的算术均值，表示该时间桶的平均功率。
- `latest_power` 使用与当前源频率和目标粒度一致的 80% 覆盖要求。
- SOC 合法但功率缺失时，SOC 仍可用于最后真实状态和最后值降级，但该桶不得进入
  功率系数拟合。
- 功率合法但 SOC 缺失时，功率可进入日期模板，但不得进入功率到 SOC 的关系拟合。
- 两座电站的数据、模板、系数和回测结果始终隔离。

### 时间对齐

时间桶 `t` 的平均功率解释为该桶内的能量流，桶末 SOC 与前一桶末 SOC 的差值对应
该桶功率：

```text
delta_soc(t) = soc_end(t) - soc_end(t - 1)
```

预测从最后一个已完成桶的真实 SOC 开始，先取得下一个桶的预测功率，再计算下一个桶末
SOC。定时和自定义路径必须使用相同定义。

## 功率模板

未来 `latest_power` 不可直接取得，因此先从历史构造条件季节中位数模板。

日期类别固定为：

- `regular`：周一至周六；
- `sunday`：周日。

对每个电站、日期类别和日内时间槽，取训练截止时刻之前同类真实功率的中位数：

```text
power_hat(day_type, slot) = median(real latest_power of same day_type and slot)
```

只使用训练截止时刻之前的数据。模板使用最近最多 28 天可靠历史；不足 14 天可靠历史时
不构造新 SOC 候选。每个待预测时间槽必须至少存在一个同类真实历史样本，否则该候选
在整个任务上不可用，不允许把 regular 模板冒充 sunday 模板，也不允许在一条曲线内
拼接最后值和功率模型。

模板使用中位数而非均值，以降低临时调度、异常尖峰和通讯错误的影响。第一版不对长
缺口做昨日或上周填补；1 至 2 个连续缺口可以仅在模型输入中做时间线性插值，必须标记
为填补值，且不能作为回测实绩。SOC 或功率仍有未解决长缺口时，关系拟合和
AutoARIMAX 只使用最后一个未解决缺口之后的连续共同尾段；功率模板仍可使用缺口两侧
各自真实有效的同类时间槽。

## 候选一：SocPowerStateModel

该候选属于灰盒系统辨识模型。对每个电站分别构造：

```text
charge_energy(t) = max(-power(t), 0) * interval_hours
discharge_energy(t) = max(power(t), 0) * interval_hours

delta_soc_hat(t) =
    beta_charge * charge_energy(t)
  - beta_discharge * discharge_energy(t)
  + idle_drift
```

`beta_charge` 和 `beta_discharge` 必须为有限正数，单位是“每 kWh 引起的 SOC
百分点变化”，已经隐含可用容量和效率，因此不要求预先知道电池容量。

系数辨识只使用相邻 SOC 都是真实有效值且当前桶功率真实有效的样本。充电样本要求负功率
伴随非负 SOC 变化，放电样本要求正功率伴随非正 SOC 变化；方向矛盾、非有限值、SOC
越界和填补样本全部排除。每个最终功率模板会使用到的方向至少需要 20 个有效关系样本。
充电和放电系数分别取有效单桶比率的中位数，`idle_drift` 取待机样本 SOC 变化的
中位数。待机阈值为 `max(1 kW, 历史绝对功率 P95 的 1%)`。

预测从最后一个非填补的真实 SOC 开始递推：

```text
soc_hat(t + 1) = clip(soc_hat(t) + delta_soc_hat(t + 1), 0, 100)
```

第一版只执行 0 至 100 裁剪，不从不充分数据中猜测实际运行上下限。原始未裁剪值和裁剪
标记继续保留。

## 候选二：AutoARIMAX

该候选使用 StatsForecast `AutoARIMA` 的外生变量能力，不再运行旧的单变量 SOC
AutoARIMA：

- 训练目标为真实/合规清洗后的 `storage_soc`；
- 历史外生变量为对齐的 `latest_power`；
- 未来 `X_df` 为同一截止时刻生成的功率模板；
- 不允许把验证窗口的真实功率作为未来 `X_df`，防止数据泄漏；
- 模型输出使用和状态模型相同的 0 至 100 裁剪；
- AutoARIMA 构建、拟合、回测或预测失败时，只跳过该候选并记录安全失败类型。

AutoARIMAX 提供统计候选，但不承担能量守恒保证。最终是否采用完全由公平回测决定。
SeasonalNaive、AutoETS、无外生变量 AutoARIMA 和 MSTL 不再作为 SOC 候选或降级策略。

## 回测与冠军选择

每个电站独立选冠军。每个回测窗口必须按时间顺序切分：

1. 只用截止时刻之前的 SOC 和功率构造模板、辨识系数或拟合 AutoARIMAX；
2. 使用该截止时刻可获得的最后真实 SOC；
3. 生成与正式任务相同粒度和预测时长的完整曲线；
4. 与窗口之后的真实 SOC 对齐评分；
5. 填补或无效实绩不参与任何指标。

每个滚动窗口的训练截止时刻之前必须仍有至少 14 天可靠历史。使用所有满足该条件且能
覆盖正式任务预测时长的最近滚动窗口，最多保留最近 7 个预测起点。若当前配置没有任何
合格回测窗口，新候选不得成为正常冠军，使用最后值降级。所有候选与最后值基线必须
使用完全相同的起点、目标点和有效点集合。

SOC 选模排序：

1. MAE（SOC 百分点）更低者优先；
2. MAE 相同则 P90 绝对误差更低者优先；
3. 仍相同则优先 `SocPowerStateModel`，其次 `AutoARIMAX`；
4. 任一新候选只有在聚合 MAE 严格低于最后值基线时才可成为正常冠军。

继续计算和展示 MAPE、WAPE、SMAPE、中位 APE，但这些指标不决定 SOC 冠军。MAPE
排除实际 SOC 等于零的点，MAE 和 P90 仍包含合法零 SOC。

## 降级和失败语义

- 可靠历史少于 14 天：不启用新候选。
- 功率模板缺少待预测日期类别或时间槽：相应候选整条曲线不可用。
- 功率/SOC 配对不足或辨识系数不符合物理约束：状态模型候选不可用。
- AutoARIMAX 失败：只跳过 AutoARIMAX，不影响状态模型。
- 两个新候选都不可用、未打败基线或最终冠军预测失败，但存在最后真实 SOC：发布整段
  “最后真实 SOC 保持不变”的曲线，状态为 `degraded`，原因使用稳定安全错误码。
- 不存在最后真实 SOC：返回 `insufficient_history`，不生成 SOC 点。
- 不允许回退到任何旧单变量 SOC 策略。
- 不允许发布部分 SOC 曲线，也不允许不同模型在同一条预测曲线中拼接。

最后值降级是透明的安全输出，不是可被标记为 `ok` 的冠军。其模型名固定为
`LastValue`。

## 共用核心接口

统一 SOC 核心使用三个内部、与发布契约解耦的对象：

- `SocTrainingFrame`：`ds`、`soc`、`power_kw` 及各自真实/填补标记；
- `SocForecastConfig`：预测起点、时间间隔、预测点数和回测上限；
- `SocForecastResult`：模型名、状态、标准 SOC 点、降级原因和模型清单。

定时和自定义适配器分别将 `SocForecastResult` 映射为现有
`ForecastSeries`/`CustomForecastSeries`。统一核心负责：

- 数据资格判断；
- 功率模板；
- 两个候选的训练和预测；
- 公平回测与选模；
- 最后值降级；
- 0 至 100 后处理；
- 可序列化的模型清单。

定时和自定义服务只负责读取、规范化、调度和持久化，不能各自实现另一套 SOC 锚定、
裁剪或评分逻辑。负载继续走现有独立路径。

## 持久化和兼容

公开预测仍只有：

- `station_total_load`；
- `storage_soc`。

不新增数据库表或列。扩展内容写入现有 JSON 模型清单，至少包含：

- `selection_policy = "soc_power_v1"`；
- 功率字段、单位和符号约定；
- 日期类别和模板历史范围；
- 有效 SOC/功率关系样本数；
- 状态模型充电系数、放电系数和待机漂移；
- 每个候选及最后值基线的 MAE、P90 和 MAPE；
- 最终模型、选择原因或降级原因；
- StatsForecast 版本（AutoARIMAX 适用时）。

历史任务保持可读且不重算。新策略性能聚合读取评估记录时，必须同时读取或回查关联的
自定义任务/正式批次，并检查其模型清单中的
`selection_policy = "soc_power_v1"`；缺少策略字段的旧任务不得混入。该隔离逻辑不依赖
评估表新增列。页面继续显示原有两条序列，并可将新模型名显示为“功率状态模型”
“AutoARIMAX”或“最后值降级”。

## 测试策略

实现必须测试先行，并至少覆盖：

- 原始 `latest_power` 的 kW 单位、负充正放、桶均值、覆盖率和异常值处理；
- `latest_power` 不成为第三条公开序列；
- 两座电站的数据、模板、系数、冠军和降级结果完全隔离；
- 周一至周六模板、周日模板及跨周预测；
- 模板只使用截止时刻之前的数据；
- 功率与 SOC 变化的桶对齐；
- 充电增加 SOC、放电降低 SOC、待机漂移和 0 至 100 裁剪；
- 未知容量条件下的系数辨识及最低样本数；
- 填补实绩不进入辨识和评分，长缺口不做季节性填补；
- AutoARIMAX 同时接收历史 `latest_power` 和未来模板 `X_df`；
- AutoARIMAX 不读取验证窗口真实未来功率；
- 两候选公平使用相同评分点，并按 MAE、P90、固定顺序选择；
- 未打败最后值基线时发布 `LastValue/degraded`；
- 无最后真实 SOC 时返回 `insufficient_history`；
- 定时和自定义路径对等价输入产生相同 SOC 值、状态和模型身份；
- 负载预测、现有 API、数据库集合和旧任务读取行为不变；
- 新旧策略性能不混算。

## 发布策略

1. 先在历史数据上运行不写正式预测表的影子回测。
2. 分别检查两座电站的 MAE、P90、MAPE、按预测步长误差和裁剪比例。
3. 只有至少一个新候选在每座电站上分别严格优于最后值基线，才允许该站正常发布
   新冠军。
4. 未达到条件的电站继续发布明确标记的最后值降级，不恢复旧策略。
5. 正式启用后继续按策略版本监控，两个电站允许选择不同冠军。

## 已确认决策

- `latest_power` 是储能功率，单位 kW，负值充电、正值放电。
- 只有历史和实时功率，没有未来 EMS 计划。
- 周日计划不同，周一至周六基本相同。
- 电池容量和现场运行 SOC 上下限暂不明确，由数据隐式辨识系数，第一版不猜边界。
- 定时预测和自定义预测共用 SOC 核心。
- 旧单变量 SOC 策略全部弃用。
- 新候选为功率状态模型和带预测功率外生变量的 AutoARIMAX。
- 历史结果保留读取但不重算、不进入新策略汇总。
