# M3 周周期负载预测设计

## 背景

M3 自定义预测任务当前将负载和储能 SOC 作为两个时间序列处理，但负载在有效历史不足 28 天时固定退回日周期 `SeasonalNaive`。该模型把昨天同一时刻平移到今天。本次生产任务配置了 28 天历史，清洗后只剩约 24.7 天连续有效历史，因此最终没有运行完整选模，负载预测实际复制了昨天曲线。

业务确认负载通常以一周为主要周期，并要求现阶段只使用历史负载，不引入天气、生产计划、M4 策略或其他外生变量。负载与 SOC 仍由同一个任务产生并持久化，但必须采用符合各自物理含义的独立预测策略。

## 目标

- 将负载的主要季节周期从一天改为一周。
- 根据有效历史长度逐级开放轻量周模型和自动模型。
- 使用统一的历史留出周公平比较所有候选模型。
- 使用 WAPE 作为负载选模主指标，同时继续计算并展示 MAPE 和 MAE。
- 保持 30 秒至 1 小时粒度以及 1 至 7 天预测范围。
- 保持 SOC 的独立模型与最后真实状态锚定逻辑。
- 不改变现有三张自定义预测数据表结构。

## 非目标

- 不引入天气、节假日、生产计划、充放电指令或 M4 策略作为负载特征。
- 不引入深度学习或新的外部模型服务。
- 不把负载和 SOC 合并为一个联合模型。
- 不改变原始数据源字段定义。
- 不迁移或重算已有预测任务。

## 总体数据流

一次自定义预测任务继续共享电站、历史范围、粒度和预测范围，并在训练数据准备完成后分为两个序列分支：

```text
历史观测与统一时间网格
          │
          ├─ station_total_load
          │    → 可用周识别
          │    → 周周期候选模型
          │    → 留出周回测与 WAPE 选模
          │    → 1–7 天负载预测
          │
          └─ storage_soc
               → 现有候选模型
               → 最后真实 SOC 状态锚定
               → 0–100% 裁剪
          │
          └─ 同一任务结果持久化
```

“分开”只表示每个序列独立选择模型和后处理，不新增任务、接口或表。

## 可用周定义

每个候选周都是相对 `forecast_start` 向前切分的连续 7 天窗口，不按自然周一至周日切分。这样任意日期开始的预测都可以用严格相差 7 天的同星期、同时刻数据。

一个周窗口必须满足：

- 覆盖该粒度下完整的 `7 × points_per_day` 个时间槽。
- 清洗后不存在未解决的空值。
- 填补点比例不超过 5%。
- 最新一周必须可用，否则负载返回 `insufficient_history`，不得用更早一周冒充上一周。

填补值可以作为候选模型的输入，但不能作为回测实际值参加 WAPE、MAE 或 MAPE 评分。系统从最新一周向前统计连续可用周数；遇到不可用周后，不再把更早的周计入多周候选模型。

任务清单同时记录：

- 用户配置历史天数；
- 清洗后训练起止时刻；
- 连续可用周数；
- 每周实际点数、填补点数和填补比例。

## 负载候选模型

### WeeklyNaive

预测值取前 7 天相同时刻的负载：

```text
y_hat(t) = y(t - 7 days)
```

它是所有有效历史不少于一周的任务的必备候选，也是新的负载基线。

### WeeklyWeighted2

最近一周权重为 `2/3`，前一周权重为 `1/3`：

```text
y_hat(t) = 2/3 × y(t - 7 days) + 1/3 × y(t - 14 days)
```

该模型需要两周作为输入和第三周作为独立回测周，因此至少需要 3 个连续可用周。

### WeeklyMedian3

取最近三周相同时刻的中位数：

```text
y_hat(t) = median(
  y(t - 7 days),
  y(t - 14 days),
  y(t - 21 days)
)
```

该模型需要三周作为输入和第四周作为独立回测周，因此至少需要 4 个连续可用周。

### AutoARIMA

负载 AutoARIMA 使用日季节长度 `points_per_day`，并启用近似拟合，将 stepwise 搜索限制为最多 20 个模型、非季节 AR/MA 阶数最多 3、季节 AR/MA 阶数最多 1。周周期由 WeeklyNaive、WeeklyWeighted2、WeeklyMedian3 和 MSTL 候选负责；避免在仅有约 3 个拟合周时对 `7 × points_per_day` 的超长季节周期执行无边界搜索。只有连续可用周不少于 4 且粒度不细于 5 分钟时才参与选模。

### MSTL

负载 MSTL 同时使用日季节长度 `points_per_day` 和周季节长度 `7 × points_per_day`，其趋势预测器使用与独立 AutoARIMA 候选相同的受限搜索参数。只有连续可用周不少于 4 且粒度不细于 5 分钟时才参与选模。

不再把日周期 SeasonalNaive 或仅日周期的 AutoETS 作为负载候选模型。

## 候选模型开放规则

规则以清洗后的连续可用周数为准，而不是仅以用户配置天数为准：

| 连续可用历史 | 负载候选模型 |
|---|---|
| 少于 1 周 | 不预测 |
| 1–2 周 | WeeklyNaive |
| 3 周 | WeeklyNaive、WeeklyWeighted2 |
| 4 周及以上，30 秒或 60 秒 | WeeklyNaive、WeeklyWeighted2、WeeklyMedian3 |
| 4 周及以上，5 分钟至 1 小时 | WeeklyNaive、WeeklyWeighted2、WeeklyMedian3、AutoARIMA、MSTL |

当只有 1–2 周可用时，没有足够数据公平比较多周候选模型，直接使用 WeeklyNaive，状态保持 `warming_up`，选模指标为空。

30 秒和 60 秒粒度不运行 AutoARIMA 或 MSTL，避免周季节长度分别达到 20,160 和 10,080 后占满 Worker。高频任务仍完整输出 1 至 7 天的原粒度预测点。

## 回测与选模

连续可用周不少于 3 时，最近一个完整周作为共同留出周。所有候选模型只能使用留出周之前的数据生成该周预测，防止未来数据泄漏。

每个候选模型在完全相同的可评分目标点上计算：

- `WAPE = sum(abs(actual - forecast)) / sum(abs(actual)) × 100%`
- `MAE = mean(abs(actual - forecast))`
- `MAPE = mean(abs(actual - forecast) / abs(actual)) × 100%`

填补或无效的实际点从三项指标中同时排除。MAPE 还排除实际值为零的点。若所有可评分实际负载之和为零，WAPE 记为空并改用 MAE 排序，同时在模型清单中记录原因。

正常排序规则为：

1. WAPE 较低者优先；
2. WAPE 相同则 MAE 较低者优先；
3. 仍相同则按固定顺序 `WeeklyNaive`、`WeeklyWeighted2`、`WeeklyMedian3`、`AutoARIMA`、`MSTL` 选择。

候选模型在构建、拟合、回测或预测阶段失败时，只跳过该候选并保存安全的失败类型，不记录异常私密文本。WeeklyNaive 只要最新可用周存在就必须能够输出；若它也失败，任务以明确错误码失败。

选出优胜模型后，使用截至 `forecast_start` 的全部适用历史重新生成最终 1 至 7 天预测，不复用留出周预测结果。

## 基线与性能聚合

负载基线从日周期 SeasonalNaive 改为 WeeklyNaive。SOC 基线继续使用现有模型并应用相同的 SOC 状态锚定，确保当前模型与基线在相同后处理口径下比较。

模型清单新增策略标识 `selection_policy = "weekly_load_v1"`。近 7 日性能聚合只合并相同策略标识、历史天数、预测天数和时间粒度的任务，避免旧日周期基线与新周周期基线混算。旧任务仍可查看，但不进入新策略的可比指标。

## SOC 行为

SOC 不使用负载周模型。它继续执行现有候选模型预测，然后：

1. 在训练帧中从后向前找到最后一个非填补的真实 SOC；
2. 计算该值与模型首个预测值的差；
3. 将差值平移到整条 SOC 预测曲线；
4. 将发布值裁剪到 `0–100%`，同时保留裁剪前值和裁剪标记。

负载不得应用 SOC 状态锚定。

## 持久化和接口

现有自定义任务、预测点和评估表结构保持不变。扩展内容写入任务现有的 JSON 模型清单和数据源清单。

负载模型清单至少包含：

- `selection_policy`；
- 周期长度和连续可用周数；
- 候选模型列表；
- 每个候选模型的 WAPE、MAE、MAPE 或跳过原因；
- 最终模型和选中原因；
- 训练起止时刻；
- StatsForecast 版本（适用时）。

数据源清单至少包含每周实际点数、填补点数和填补比例。旧任务没有这些字段时，接口和页面必须继续兼容。

预测点接口、任务提交接口和幂等语义不变。内容哈希自然包含新的最终模型和预测点，不需要新字段。

## 界面

模型配置区域显示：

- `负载周期：7 天`；
- 当前粒度允许的候选模型；
- 高频粒度不运行 AutoARIMA/MSTL 的说明；
- `SOC 后处理：最后真实状态锚定`。

预测结果区域显示：

- 负载最终模型；
- 连续可用周数；
- 最终模型回测 WAPE、MAE 和 MAPE；
- WeeklyNaive 基线表现和相对提升；
- 被跳过候选模型的简短原因；
- SOC 模型名称后附“状态锚定”。

旧任务缺少周策略清单时显示原有信息，不伪造新指标。时间统一转换为 `Asia/Shanghai` 后展示，不能直接截取 UTC 字符串。

## 错误和降级行为

- 最新连续可用历史不足 7 天：负载返回 `insufficient_history`。
- 只有 1–2 周：使用 WeeklyNaive，状态为 `warming_up`。
- 自动模型失败：跳过并继续轻量周模型。
- 留出周无有效评分分母：使用 MAE 排序并记录 WAPE 不可用。
- 最终优胜模型预测失败：退回 WeeklyNaive，状态为 `degraded`，仅暴露安全失败类型。
- SOC 锚点不存在：SOC 序列失败，不得使用填补值冒充真实锚点。

## 测试策略

实现遵循测试先行，至少覆盖：

- WeeklyNaive 严格使用前 7 天同一时刻；
- WeeklyWeighted2 的固定权重；
- WeeklyMedian3 对异常周的鲁棒性；
- 1 至 7 天预测的点数与时间连续性；
- 可用周识别、5% 填补边界和不连续周停止规则；
- 填补实际值不进入 WAPE、MAE、MAPE；
- WAPE、MAE和固定顺序的确定性选模；
- 30 秒和 60 秒不构造 AutoARIMA/MSTL；
- 5 分钟及以上在条件满足时开放自动模型；
- 候选失败隔离和 WeeklyNaive 安全回退；
- 负载不执行 SOC 锚定；
- SOC 锚定行为保持不变；
- 新旧模型清单的接口与页面兼容；
- 新旧策略性能结果不混算；
- Node-RED 独立 HTML 与 Flow 模板保持一致。

## 发布范围

实现将涉及 Worker 的训练数据准备、负载候选模型、选模与性能聚合，以及 Node-RED 独立 HTML 和 Flow 模板中的模型配置与结果展示。无需修改数据库表，也无需重新创建集合。发布时需要重新构建 Worker 所在镜像并重新导入修改后的 Flow；旧任务数据保持可读。
