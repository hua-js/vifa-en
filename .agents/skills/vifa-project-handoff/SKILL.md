# VIFA 项目续接与文档维护

让下一位协作者能快速确定有效业务口径、未解决事项和可执行范围。项目规则和状态保留在仓库文档中；本 Skill 只保存核对与维护方法。

## 读取入口

先确认当前Git根及 `git status --short`，保留已有修改。本 Skill 位于项目 `.agents/skills/vifa-project-handoff/`，以下路径相对核实后的项目根；不要切回历史副本工作。

- `AGENTS.md`：长期协作、测试时机、文案、前端及安全边界。
- `CODEX_HANDOFF.md`：当前目标、有效口径、验证限制和下一步。
- `README.md`：模块布局和实际入口。
- 任务相关的 `docs/<module>/`、源码及已有输出证据；按需读取，不扫描全部历史。
- 仅需追溯日期、run_id、旧参数或发布记录时，检索 `docs/项目交接历史.md`。档案中的“当前”“最新”“未提交”是记录当时的措辞。

独立检查文档不需要启动应用、浏览器或运行求解器。

## 判断当前状态

- 行为约定以当前明确要求及适用项目规则为准；源码只能证明实现，不能证明业务授权。历史一次性豁免不转成长期规则。
- 对冲突条目分别确认生效范围、版本和证据，不仅按日期选一条。例如日计划与实时候选可能使用不同目标顺序，不能合并成“全M4统一”。
- 把源码完成、Git提交、镜像构建/推送、生产部署、实际运行分别表述。记录过PID或接口200不证明现在仍运行，已推旧镜像不证明包含后续HTML。
- 测试结果注明版本、范围和证据位置。专项通过与全量失败同时保留；模拟GET、截图或预测费用不能证明真实接口、设备执行或实测节省。
- 旧基线值、策略版本、端口和失败数量不写死在本Skill，按当前交接、源码和证据核对。未能核实就明确标注，不恢复被撤销实验或退役接口。

## 更新文档

只有检查请求时报告问题；用户授权修改后落实明确修正。

- `AGENTS.md`保留仍有效的长期约定与必要来源。新规则覆盖旧规则时直接统一受影响条款，避免同时留下“默认不测试”和“开发后必须测试”；设计质量要求与实际验收触发时机分开。
- `CODEX_HANDOFF.md`按当前状态、有效口径、待办/限制及证据链接维护对应段落，替换失效状态，不不断向顶部追加任务流水。保留各模块未解决事项及被用户明确取消的事项。
- 详细实现归入现有模块文档；README只保存可用入口和状态索引。交接链接的模块文档首段若与最终口径相反，一并作最小修正，历史试验保留明确标识。
- 精简大量混合历史时，必要的原始记录可合并至现有历史档案，并标明历史性质；调整搬迁后的相对链接。不要删除决策证据、制造重复方案文档或让档案再次成为默认全文入口。
- 文档维护不授权提交/推送、生产操作、写API、启动自动任务或设备下发。测试、浏览器及远程访问沿用项目和当前用户约定，不因维护Skill扩大操作范围。

## 交付前核对

回读修改及diff，检查链接目标、当前/历史分界、取消事项、权限和验证表述；确认保留原有未提交工作。新增Skill核对frontmatter及相对引用，不将格式检查称为行为验收。

简要报告修改的文件、精简结果、Skill调用名与实际检查范围。若未进行业务测试、服务或生产核验，如实说明；不为得到通过结论而额外启动环境。
